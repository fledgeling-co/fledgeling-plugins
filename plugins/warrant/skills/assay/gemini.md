# gemini.md — `assay`

Read this once, now, then read `SKILL.md` and follow it with the overrides below; each names the
section it lands on. `assay` fits this model unusually well in one respect and badly in one. Well,
because every number it produces is generated by a script that prints its own denominator, and
**[measured-family]** the one benchmark bucket where this family matches opus is the one whose brief
already states a number — optimality, 74.7 against 75.0 (`geminify/references/evidence.md` §2.1).
Badly, because the thing `assay` hands back is a *measurement record*, and a document with an obvious
shape and nothing compiling it is precisely what one measured run filled in without running anything.

## Epistemic status

- **Tiers used:** `[docs]`, `[measured-family]`, `[derived]`. No `[measured-here]`: **no Gemini run of
  `assay` has been observed**, at any tier.
- **`[measured-family]` sources:** two single sessions (n=1 each) and a 106-task benchmark at two
  effort levels — `geminify/references/evidence.md`. None of the three watched a model measure a test
  suite.
- **The tier the evidence is about.** Every measured rate below was observed on `gemini-3.7-flash`
  (one session on `gemini-3.7-flash-high`) — flash-tier claims, **not** to be projected onto the Pro
  tier. **[docs]** The default drifts inside the family: *"If thinking_level is not specified, Gemini
  3 will default to high."* against, from the 3.5 Flash release notes, *"The default thinking effort
  is now medium, changed from high in Gemini 3 Flash Preview."* On Pro these overrides stand as
  `[docs]`-grounded discipline and every `[measured-family]` number is open.
- **Unmeasured on this skill:** no Gemini run of `assay` · no evidence a `gemini.md` fixes anything on
  either source · the fabricated-review and categorical-collapse observations were made on UI briefs,
  so their transfer to a mutation report is `[derived]` · nothing measures this family running a
  mutation harness, reading a survivor set, or handling `C18`'s and `C23`'s figures.
- **The self-limitation.** **[docs]** A conditional side file is the shape the checklist warns about:
  *"Avoid writing a prompt with non-linear logic or conditionals that require the model to piece
  together fragmented instructions from multiple different places in the prompt."* One pass, then work
  from `SKILL.md`.

## There is no route-out block here

geminify writes one only where the benchmark measured the work, and `assay` fails both conditions.
**Its work class is one the corpus abstains on:** the bench measures a model *building* an artifact,
while `assay` runs three scripts and reads their numbers, which sits in `verification` — where
`lane_pick.py` returns the policy answer unchanged. **And none of the four measured shapes is a thing
it produces:** `static-page` and `visual-design` (it renders nothing), `brownfield-integration` (the
mutants are written into a temporary copy by `mutate.py`, never into the working tree),
`regression-sensitive` (it *measures* whether the contract can fail rather than preserving one).
**[docs]** *"Avoid using prompts that ask the model to perform a task for which it has a known,
fundamental limitation."*

## What transfers intact, and what the scan found

**There is nothing to quota and nothing to bound here.** The scan returns **0 categorical rows and 0
bound rows** over 101 lines, against 5 loose distributives and 12 prose prohibitions it counted
rather than listed. That is earned rather than lucky: `assay`'s scopes are already denominators.
`CI selects 420 of roughly 3,011 authored instances across 137 spec files` is a fraction, not a
scope; `Eight patterns` is a stated count; and `_cli.rate()` renders a percentage with its numerator
and denominator or refuses to render one. So no quota ledger is written below — inventing rows for a
skill that has none would bury the two overrides that matter.

**The constraint that pre-empts the worst failure is already in the file.** `What is not acceptable
is a suite that has never been measured being treated as evidence` and `A mutation score of 40% is
information; the absence of a mutation score is not` are, in the target's own words, the rule
**[measured-family]** §1.1.2 records a run breaking — five well-formed `PASS` rows over probes that
never executed. Read them as binding rather than as encouragement.

**Modules.** `gate` fired at 3 triggers and is written below. Nothing else fired and nothing else is
written: `visual` (0 — `assay` renders nothing), `states`, `platform-values`, `injection` (its inputs
are the repository's own source and spec files), `delegation`, `bounded-constraint` (no bound rows),
`count-contract` (the eight patterns and the mutation kinds are already counted by the scripts), and

## Override 1 — the delivery note is the genre that got fabricated (`## Output`)

**[measured-family]** §1.1.2 (n=1): a run wrote its own review as five well-formed rows, all `PASS`,
asserting a browser engine as verified when it had failed all four invocation attempts,
`100% pass rate on contrast` from a probe never executed — measured afterwards, every primary button
3.65:1 and one glyph 1.00:1, invisible — and `Interactive Targets Audited: 47`, a number nothing
produced. Forty cells' worth of work, five rows. A mutation report is the same genre with better
typography.

So **no figure is typed by hand**. Every number in the delivery note is copied from a script's stdout
with its command beside it. **[docs]** *"Include specific verification steps in either the system
instructions or your prompts directly."* and *"Verify your claims by quoting the exact applicable
information (including policies) when referring to them."* Ship this filled, as the shape:

```
mutate      mutate.py --root . --targets .warrant/selected.list --test-cmd 'pnpm test'
            → 61.4% (212 of 345 mutants killed) · high_water 58.9 → 61.4 · exit 0
            → by kind: conditional 74/96 · boundary 51/88 · return 47/71 · operator 40/90
cannotfail  cannotfail_scan.py --root . --glob 'apps/web/e2e/**/*.spec.ts'
            → 9 findings across 137 spec files · no-matcher 4 · self-compare 2 · skip 3 · exit 0
gap         selection_gap.py --root . --authored authored.list --selected selected.list
            → 2,591 authored instances never selected, across 11 surfaces · exit 0
rollup      rollup_classes.py --root .   → 6 classes written · green true on 2 · exit 0
control     mutate.py --selftest   → exit 0
```

A run that cannot show `mutate.py`'s exit code is holding an unmeasured suite, and says so in the
first line rather than the last. **[docs]** *"provide instructions for handling missing data rather
than assuming inserted data will always be present and well-formed."* — an absent score is reported
as absent, never as a pass.

## Override 2 — mutate the selected set, and name which set that was (`### 1 · Mutate the set CI actually runs`)

The step's whole point is a choice of population, and `assay`'s own sentence is the warning:
`Mutate against the selected set, not the authored one` — because `the selected set is what gates a
merge`. The two differ by roughly sevenfold in the target repository. Passing `--targets` a directory
walk is the easy, wrong reading, and it produces a *higher* score over code CI never runs.

So the delivery note names the file `--targets` was given and its line count, beside the score. A
mutation score whose population is unstated is `C19` in miniature. **[docs]** *"Avoid using
subjective or relative qualifiers that lack a concrete, measurable definition."* — and the objective
constraint here is the path, not the adjective.

`--max-mutants` samples round-robin across kinds. When you cap it, the cap goes in the note too: a
score over 200 sampled mutants and a score over 3,000 are different numbers with the same name.

## Override 3 — prove the gate can fail, then check the rollup receipt (`### 4`, `### 5`)

**[measured-family]** §1.2.2: an auditor validated tags, citations and contrast floors thoroughly,
had no check that its prerequisite artifacts existed, and returned exit 0 over two skipped skill
invocations. **[derived]** geminify's own quote gate went green across every file after a change took
its checked count to zero, caught only by re-running the negative control (§5). Every script in this
plugin ships the control already:

```bash
python3 scripts/mutate.py --selftest          # exit 0 only if every rule fired
python3 scripts/cannotfail_scan.py --selftest
python3 scripts/selection_gap.py --selftest
```

Then read the receipt before the verdict. `rollup_classes.py` is the step whose omission is invisible:
`suite-health.json` can be green and every defect class still read as having no evidence, because
authority is held per class and the producer writes per target. That exact divergence is on record as
this plugin's one integration defect. So the note carries the `classes` block's own numbers, and a
class no target matched reads `green: false` rather than absent — **[docs]** *"When model outputs must
be machine-readable or follow a specific format, use a widely recognized standard like JSON, XML,
Markdown or YAML that can be parsed by common libraries."*, which here is `.warrant/suite-health.json`
rather than the prose summary. Count over it in Python: **[docs]** *"Gemini's code execution tool
enables the model to generate and run Python code, and should be enabled whenever the model needs to
perform any kind of arithmetic, counting, or calculation."*

## Override 4 — a low score is the answer, and exit 2 is a finding (`## What a bad first number means`)

**[docs]** *"On *other* errors, you must change your strategy or arguments, not repeat the same failed
call."* **[measured-family]** Both n=1 sessions ran the loop: four consecutive invocations of one
banned, absent tool with nothing changed between them (§1.1.2), and four consecutive `Read` calls
against a 25,000-token ceiling before pivoting to a Python split (§1.2.3). `gemini-cli` ships a loop
detector whose halt message names *"repetitive tool calls"* (§7.2).

Where that lands here is specific and it is not about transient errors. **`mutate.py` exit 2 means the
score dropped below the recorded high-water mark. Do not re-run it.** A second run with a different
`--max-mutants`, a narrower `--targets` or a longer `--timeout` will return a different number, and
choosing among them is the ratchet defeated by the model it exists to constrain. The target's own
line is the rule: `It means the measurement worked.` Record it, report it, and the fix belongs to the
tests.

Two attempts on a genuinely transient failure, one on a permanent one. A `--test-cmd` that fails on
the unmutated baseline is permanent: fix the command, do not retry it. A whole-repo `--copy-mode full`
that exhausts disk pivots on attempt 1 to `sparse`, not on attempt 4.

## Override 5 — read one survivor in full before summarising the set (`### 1`, `## Constraints`)

**[docs]** *"We recommend to always include few-shot examples in your prompts."*, and *"you can remove
instructions from your prompt if your examples are clear enough in showing the task at hand"*. The
aggregate hides the finding: `An aggregate score hides the case where one operator class is never
killed, which is the finding worth acting on.` So write one survivor at full fidelity first, and let
the rest match its shape:

| kind | file:line | mutation | tests run | killed by | reading |
|---|---|---|---|---|---|
| boundary | `src/lot/sample.ts:41` | `n >= min` → `n > min` | 420 | none | no test exercises the boundary; the sample size is off by one and green |
| conditional | `src/ledger/chain.ts:88` | `if (prev)` → `if (true)` | 420 | `ledger.spec.ts:12` | chain verification is sensitive here |

**[docs]** *"Avoid providing examples that show the model generating its final, structured answer
before it has completed its step-by-step reasoning."* — the survivor table comes before the verdict
about the suite, not after it.

And treat `cannotfail_scan.py` output as the target says: `candidates rather than defects`. Each row
gets a reading, or it is reported as unread. A count of nine findings presented as nine defects is a
claim about code nobody looked at.

## Override 6 — the figures are read, never recalled (`# Assay`, `## Constraints`)

**[docs]** *"Your knowledge cutoff date is January 2025."*, and from the 3.7 Flash model card, *"The
knowledge cutoff date for Gemini 3.7 Flash is March 2026 — users can expect updated information for
some domains while in others they may experience the model's knowledge is limited to January 2025 (in
line with the Gemini 3 Model Family)."* **[measured-family]** §1.1.4 recorded the failure mode that
matters more than a guess: a previous-generation published value returned confidently, eight metric
errors in one artifact.

`C18` and `C23` are claim ids, and they resolve in `warrant/references/evidence.md` and
`docs/deep-research/claims.json`. Read the row before restating the number — the bound on `C18` is
`One company's codebase. No rate exists for browser or end-to-end suites`, and a run that drops that
clause has turned a bounded finding into a general law. **[docs]** *"Do not assume or infer from the
provided facts; simply report them exactly as they appear."*

The same rule covers a file named in a prompt. **[measured-family]** §1.2.4 recorded both halves
failing in one session — answering from memory when three skills were named, then launching a skill
when an answer was wanted. Read, then answer, as two ordered steps.

## Override 7 — `thinking_level`, and what it is not for

**[docs]** `HIGH` is described as suitable for *"multi-step planning, verified code generation, or
advanced function calling scenarios"*; 3.7 Flash defaults to `MEDIUM`. `assay` is not that — it runs
four commands in a fixed order and reads their output — so run the default. **[measured-family]** Do
not raise it as a remedy for anything above: paired across 106 tasks, `high` beat `medium` on 24,
lost on 24 and tied on 58, mean −1.7 points (§2.3). **[docs]** *"Higher thinking levels encourage the
model to use more tools to explore and verify, so lowering the level can reduce tool calls."* — which
is the wrong direction for a skill whose expensive step is a mutation run.

## Recap

format, at the end of the prompt."*

1. Type no figure by hand; ship the delivery note filled, each number beside the command that
   produced it, and name an absent measurement as absent.
2. Mutate the selected set, and put the target list's path and line count beside the score, with any
   `--max-mutants` cap.
3. Run `--selftest` before believing a clean gate, and run `rollup_classes.py` before believing any
   class has evidence.
4. Exit 2 is a finding. Do not re-run `mutate.py` for a better number; two attempts on a transient
   error, one on a permanent one.
5. Read one survivor in full before summarising, treat cannot-fail hits as candidates, and read `C18`
   and `C23` out of `references/evidence.md` with their bounds attached.
