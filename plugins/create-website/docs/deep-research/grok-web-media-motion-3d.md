Muted or silent media is the autoplay path in Chrome, Firefox, and Safari. iPhone stays inline only with `playsinline`. ## Detailed Findings

### How should an agent building a multi-section website use generated video, scroll-driven motion, real-time 3D and generated imagery so the result is fast, accessible and robust in late 2026?

Treat each effect as an enhancement on a page that is already readable as HTML and stills. The decision table is the operating rule.

| Layer | Paint first | Start motion when | Stop when | Accessible stand-in |
| --- | --- | --- | --- | --- |
| Hero / background video | `poster` with width and height | `autoplay` + muted or no audio track + `playsinline`; `play()` rejection shows the poster | Off-screen, tab hidden, reduced motion, or the pause control | Poster plus a pause control if the loop exceeds 5 s |
| Generated stills | `<img>` / `<picture>` in HTML, dimensions set, hero URL discoverable without CSS | Not applicable | Not applicable | `alt` for information; empty `alt` only when the image is decorative |
| Scroll motion | Final state of the section, in normal flow | `prefers-reduced-motion` is not `reduce`, and scroll-timeline support is detected | Reduced motion: no parallax, no scrub, no pin | The section’s HTML in source order |
| WebGL | The same still, in HTML, reserved box | `getContext("webgl2")` returns a context and the canvas is near the viewport | Off-screen, `webglcontextlost`, or reduced motion for non-essential camera moves | Fallback content or adjacent HTML that states what the canvas showed |

[web.dev, LCP](https://web.dev/articles/lcp) [MDN, media queries for accessibility, 19 Nov 2026](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using_for_accessibility) [HTML, canvas](https://html.spec.whatwg.org/multipage/canvas.html)

#### 1. Background and hero video

**Autoplay.** MDN’s guide, revised 10 Sep 2026, states that autoplay blocking is not applied to a `<video>` with no audio track or with the audio muted, and that audible media is blocked unless the user has interacted with the site, the site is allowlisted, or an iframe has been delegated permission. [MDN](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) Chrome’s policy, still the document MDN points at, is: muted autoplay is always allowed; autoplay with sound depends on a user gesture, the Media Engagement Index, or an installed home-screen / PWA scope. [Chrome, 13 Sep 2017](https://developer.chrome.com/blog/autoplay) The same era of Chrome on Android pauses an autoplaying muted video when it leaves the viewport. [Chrome 58 media updates, 21 Mar 2017](https://developer.chrome.com/blog/media-updates-in-chrome-58)

Safari on macOS and iOS plays `<video autoplay>` only when `playsinline` is also set. Autoplay runs only if there is no audio track or `muted` is set. Playback pauses if the element is unmuted without a gesture or is no longer on screen. Without `playsinline`, iPhone playback is fullscreen. [Apple](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) `HTMLMediaElement.play()` returns a promise. On denial the rejection name is `NotAllowedError`; the page should leave the poster up and offer a control. MDN recommends the `autoplay` attribute over a scripted `play()` when the browser can start playback itself. [MDN](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

`navigator.getAutoplayPolicy("mediaelement")` returns `allowed`, `allowed-muted`, or `disallowed`. Where it exists, mute when the result is `allowed-muted` and do not call `play()` when it is `disallowed`. [MDN, getAutoplayPolicy, 10 Nov 2026](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/getAutoplayPolicy) Firefox’s `media.autoplay.allow-muted` defaults to true, so a muted track may play. If a user sets it false, a file that still contains an audio track will not autoplay even when muted. A decorative hero with the audio track removed stays in the “no audio track” bucket instead. [MDN, Firefox preferences](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

**Encoding and responsive files.** Apple’s current Safari article says static files should be H.264 MP4, and that GIFs can be up to 12 times as expensive in bandwidth and twice as expensive in energy as a modern video codec. [Apple](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) MDN’s codec-selection page (12 Aug 2026) describes H.264 as the compatibility codec, AV1 as better compression than H.264 and VP9 with decode support it tabulates at 87.8% for `av01.0.08M.08` (1080p), and HEVC as an MP4 codec whose patent status developers should review with counsel. [MDN, codec selection](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API/Codec_selection)

The HTML resource-selection algorithm skips a `<source>` whose `media` does not match the environment, then skips a `type` the browser knows it cannot render, and this happens before the fetch. VBench (Huang et al., CVPR 2024, pages 21807–21818) splits video quality into temporal quality and frame-wise quality. Temporal flickering is local, high-frequency inconsistency across frames. The reference implementation walks every decoded frame and averages mean absolute error. #### 3. Scroll-driven motion

MDN documents scroll-driven animations as CSS animations whose timeline is scroll progress or view progress rather than the document clock. The timelines guide says a JavaScript scroll listener or `IntersectionObserver` runs on the main thread and can jank, and that the scroll-driven model avoids that for the animation itself. Firefox applies the effect only when `animation-duration` is non-zero, so the documented cross-browser value is `1ms`. [MDN, scroll-driven timelines, 7 Oct 2026](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations/Timelines) `scroll()` and `view-timeline` are marked Baseline 2026, newly available since October 2026. [MDN `scroll()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline/scroll) [MDN `view-timeline`, 17 Nov 2026](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/view-timeline)

Chrome’s scrollytelling guide (8 Nov 2026) tells authors to feature-detect with `@supports ((animation-timeline: scroll()) and (animation-range: 0% 100%))`, to skip the `scroll-timeline-polyfill` because it is incomplete, to animate `transform` and `opacity`, and to use the native implementation wherever it exists. [Chrome](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/scrollytelling) A separate Chrome article announced scroll-triggered animations (time-based animations that fire at a scroll offset) for Chrome 145, which is a different feature from scrubbed scroll-driven animation and is not Baseline. [Bramus, Chrome, 12 Dec 2025](https://developer.chrome.com/blog/scroll-triggered-animations)

web.dev’s rendering article gives the frame budget as about 10 ms of author work inside a 16.7 ms frame at 60 Hz, and repeats the INP “good” line of 200 ms or less. Poor INP is above 500 ms. Both are p75, field, split by device. [web.dev, rendering performance, 13 Dec 2023](https://web.dev/articles/rendering-performance) [web.dev, INP](https://web.dev/articles/inp) <INFERENCE from="10 ms frame budget; INP input-delay definition; Chrome’s warning against scroll listeners">A scroll handler that reads layout and writes it on the same turn, or that calls `preventDefault` on `wheel` or `touchmove`, competes with the next paint. The page should scroll natively. Pin by `position: sticky` plus a scroll timeline when that is the whole effect.</INFERENCE> <MISSING_DATA>No primary source in this pass published an INP delta, in milliseconds, for a ScrollTrigger pin versus a CSS scroll timeline on a named device.</MISSING_DATA>

`prefers-reduced-motion: reduce` means the user asked for non-essential motion to be removed or replaced. It has been widely available since January 2020. MDN’s accessibility guide says the expectation matches WCAG’s animation-from-interactions rule, and that `* { animation: none !important }` is broader than the preference. [MDN, prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion) [MDN, using media queries for accessibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using_for_accessibility)

WCAG 2.3.3 is Level AAA: motion animation triggered by interaction can be disabled unless essential. Parallax is the example in the understanding document. Sufficient techniques include C39, the `prefers-reduced-motion` query. [W3C quickref, 2.3.3](https://www.w3.org/WAI/WCAG22/quickref/#animation-from-interactions) [W3C technique C39, 2 Jul 2026](https://www.w3.org/WAI/WCAG21/Techniques/css/C39) The criterion is AAA, so it is not required for a typical AA conformance claim. 2.2.2 is Level A and already covers motion that starts on scroll-into-view and lasts more than five seconds. [W3C, Understanding 2.2.2](https://www.w3.org/WAI/WCAG21/Understanding/pause-stop-hide.html) GSAP’s `gsap.matchMedia()` documentation (page updated 11 Nov 2026) shows a `reduceMotion: "(prefers-reduced-motion: reduce)"` condition and sets duration to `0` when it matches. [GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia())

GSAP ScrollTrigger’s `pin` changes document flow via pin spacing. [GSAP forum, refreshPriority](https://gsap.com/community/forums/topic/37060-gsap-scrolltrigger-issue-with-matchmedia-and-pinned-elements/) [GSAP forum, 3.12.4 fix, 15 Dec 2023](https://gsap.com/community/forums/topic/39323-scrolltrigger-matchmedia-nextjs-works-and-stops-on-resize/) <INFERENCE from="pin spacing changes layout; CLS ignores size changes that do not move other elements’ start positions">A pin that pushes the following section down at runtime is a layout change. #### 4. WebGL and three.js

`window.devicePixelRatio` is physical pixels per CSS pixel. MDN notes that 2 is the usual HiDPI value and that higher values occur. [MDN, devicePixelRatio, 13 Nov 2026](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio) `WebGLRenderer.setPixelRatio` multiplies the drawing buffer by that value. [three.js WebGLRenderer docs, 6 Nov 2026](https://threejs.org/docs/pages/WebGLRenderer.html) <INFERENCE from="buffer width = CSS width × pixel ratio">Going from 2 to 3 multiplies fragment work by 2.25 for the same CSS box. The cap is a pixel-count control, not a quality setting in the spec.</INFERENCE>

React Three Fiber’s default is `Math.min(2, Math.max(1, devicePixelRatio))`. In August 2024, an iPad report showed immediate context loss when that default was combined with `antialias: true` and `powerPreference: "high-performance"`. The maintainer’s workaround on those devices was `powerPreference: "default"` and `antialias: false`. [react-three-fiber issue 3309](https://github.com/pmndrs/react-three-fiber/issues/3309) three.js already calls `preventDefault` on `webglcontextlost` and logs `WebGLRenderer: Context Lost.` [three.js WebGLRenderer.js](https://github.com/mrdoob/three.js/blob/dev/src/renderers/WebGLRenderer.js) `getContext` returns null when the context id is unsupported or the canvas already has a different context type. [HTML, getContext](https://html.spec.whatwg.org/multipage/canvas.html) <INFERENCE from="getContext null; context-lost log; iPad context-loss report">On null or context loss, stop the animation loop and show the poster. A spinning `requestAnimationFrame` into a dead context does no pixels and still schedules frames.</INFERENCE>

On the 2020 sample set, Draco was sometimes smaller after gzip and Meshopt was much faster to decode (about 25× on one model and about 39× on another in that comment). [glTF PR 1830](https://github.com/KhronosGroup/glTF/pull/1830) Use Meshopt when decode time on a phone matters, Draco when the asset is a triangle mesh and the byte saving shows up in a measurement of that file. Keep the poster regardless. Gzip or Brotli still applies on the wire. The Meshopt README says the codec is built to remain friendly to that second compression. [KHR_meshopt](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_meshopt_compression)

The canvas element represents its fallback content when scripting is disabled, canvas is disabled, or the canvas is not showing a bitmap. In non-visual media it represents the fallback content. Authors who make regions interactive are told to map them to focusable controls in that fallback. [HTML, canvas](https://html.spec.whatwg.org/multipage/canvas.html) <INFERENCE from="fallback is not displayed for a live WebGL bitmap">A successful WebGL canvas does not show its fallback to a sighted mouse user. The accessible name has to be a real element: a heading and a paragraph beside a decorative canvas, or fallback content that is programmatically associated for the information the picture carries. `aria-hidden="true"` fits a decorative canvas only when the same information is not trapped inside it.</INFERENCE>

Custom-domain states worth branching on:

Vercel expects an `A` or `CNAME` as shown on the project’s domain page. Non-wildcard certificates use an HTTP-01 challenge that succeeds only when the name already points at Vercel. Wildcard certificates need DNS-challenge access, either Vercel nameservers or a delegated `_acme-challenge`. A CAA record is fine when absent. If present, it must allow `letsencrypt.org`. An unverified domain does not get a certificate. [Vercel domain troubleshooting, 18 Sep 2026](https://vercel.com/docs/domains/troubleshooting)

Netlify provisions Let’s Encrypt after DNS points at Netlify. External DNS: apex `A` to `75.2.60.5`, `www` as a CNAME to the site’s `netlify.app` name. Failed attempts retry every 10 minutes for 24 hours, then hourly for two days. The docs call out “Waiting on DNS propagation” past 48 hours, DNSSEC (unsupported on Netlify DNS), CAA, and a proxy that terminates TLS in front of Netlify. [Netlify SSL troubleshooting, 21 Mar 2026](https://docs.netlify.com/manage/domains/troubleshooting/troubleshoot-ssl-and-https/) [Netlify HTTPS](https://docs.netlify.com/manage/domains/secure-domains-with-https/https-ssl)

<INFERENCE from="Vercel and Netlify both issue after DNS is correct; both fail closed on CAA and on a proxy that hides the HTTP-01 token">An agent should treat domain setup as a state machine: added, DNS pending, certificate pending, certificate ready, or failed with the host’s reason. “The site loads on the default `*.vercel.app` or `*.netlify.app` host” does not mean the custom name is ready, and “noindex is set” does not mean the default host is private.</INFERENCE>

### What is the current state, and what is the strongest supporting evidence?

As of documents dated through 20 Nov 2026, the interoperable hero is muted, inline, H.264-backed, poster-first, and range-request-friendly. The strongest evidence is the combination of the HTML resource-selection algorithm (20 Nov 2026), Apple’s Safari video article, MDN’s autoplay guide (10 Sep 2026), and WebKit bug 211323’s statement that Safari requires range support. Scroll-driven CSS is Baseline on current browsers since October 2026 and still feature-detected by Chrome’s own November 2026 guide. WebGL has no published mobile budget. The measured failure mode on record here is context loss when pixel ratio, antialiasing, and a high-performance context coincide on an iPad. Deployment privacy is a product setting on Vercel and Netlify. `noindex` is a crawler directive, documented by Google and restated by both hosts.

### What changed recently, and what is the trajectory?

WCAG 2.2 itself was published on 5 Oct 2023, with an editorial update on 12 Dec 2024. The success criteria used here, 2.2.2 and 2.3.3, were not newly invented in that update. The W3C FAQ says the group is not planning a WCAG 2.3 and is working on WCAG 3. [W3C WCAG FAQ, 20 Nov 2026](https://www.w3.org/WAI/standards-guidelines/wcag/faq/)

INP replaced FID as a Core Web Vital on 12 Mar 2024, with the 200 ms good threshold. [web.dev, 12 Mar 2024](https://web.dev/blog/inp-cwv-launch) Scroll-driven animations moved from Chrome-only (115, 2023) to a Baseline 2026 feature in MDN’s October 2026 pages, while scroll-triggered animations were announced for Chrome 145 in December 2025 and are not yet the thing to depend on. [Chrome, 12 Dec 2025](https://developer.chrome.com/blog/scroll-triggered-animations)

Chrome’s lazy-loading guide for `<video>` and `<audio>`, dated 2 Nov 2026, is the newest loading change: `loading="lazy"` defers the poster, preload, and autoplay until the element is near the viewport, and the guide tells authors to respect `prefers-reduced-motion` before autoplaying. Firefox has the attribute as an off-by-default experiment. [Chrome, 2 Nov 2026](https://developer.chrome.com/docs/modern-web-guidance/guides/performance/lazy-load-video-and-audio) [MDN Firefox experimental features](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Experimental_features)

Video generation’s control surface that matters for websites is first-and-last-frame interpolation on Veo 3.1 and Gemini Omni, documented by Google Cloud on 20 Nov 2026, plus extend-from-last-second on DeepMind’s Veo page. [Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/generate-videos-from-first-and-last-frames) VBench-2.0 (March 2025) argues that temporal coherence scores can look convincing while physics and commonsense still fail, which is a reason to watch the clip rather than trust a frame sample or a benchmark aggregate. [VBench-2.0 project page](https://vchitect.github.io/VBench-2.0-project)

On hosting, Vercel’s password-protection pricing in the September 2026 docs is $20 per protected project per month on Pro, with Hobby excluded. Netlify’s deploy overview, current as of 10 Nov 2026, still refuses to treat `X-Robots-Tag` as protection and points preview privacy at project visibility or a password. [Vercel](https://vercel.com/docs/deployment-protection) [Netlify](https://docs.netlify.com/deploy/deploy-overview/)

The direction through late 2026 is stable on the fundamentals: muted inline video, poster as the LCP candidate, range requests for Safari, reduced motion, and a real access control for anything unreleased. The moving edge is declarative scroll animation becoming safe to prefer over scroll listeners, and generated video becoming controllable at the cut points. Neither removes the need for a still fallback.

## Knowledge Gaps

- **Not measured here.** A hero byte budget, a CRF that holds a named quality score at 720p and 1080p, and an LCP delta for AV1 versus H.264 on a slow phone profile. The docs constrain LCP and CLS, not file size.
- **Not measured here.** INP and GPU time for ScrollTrigger pin versus CSS `animation-timeline` on a mid-range phone. The 10 ms frame budget is general, not a result from a marketing page.
- **Not published as a number.** A mobile GPU memory or triangle budget for marketing WebGL. The evidence is a failure mode (iPad context loss), not a ceiling.
- **Withdrawn bug, not a spec.** Whether iOS Low Power Mode blocks muted autoplay. The August 2026 WebKit report was closed by its reporter as a device setting.
- **Vendor-stated, not independently checked.** Meshopt’s ~1 GB/s decode figure, and the 2020 Draco-versus-Meshopt timings. They are one engineer’s measurements on named models.
- **Model coverage.** First-and-last-frame behavior is documented here for Google Veo 3.1 and Gemini Omni. Equivalent parameters for other generators were not taken from those vendors’ own docs in this pass, so they are not in the rules.
- **Tooling gap.** The Dossier research panel was not run. The MCP router failed to connect, so this pass used primary pages directly rather than a multi-model research loop.
- **Stale support matrices.** The Chrome scroll-animation case study’s Safari and Firefox line disagrees with MDN’s October 2026 Baseline mark. Current-channel support should be re-checked before dropping the `@supports` test.
