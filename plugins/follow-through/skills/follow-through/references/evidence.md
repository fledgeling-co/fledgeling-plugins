# Design basis and limits

These skills operationalise the six-area authoring brief, including its explicit
freshness, identity, scope, privacy and approval requirements. They make no new
empirical productivity or model-performance claims. Neutral fixtures replace
private observed history; no original messages or screen contents are bundled.

Existing repository skills were inspected for boundaries: `shipyard:shipyard`
owns feature stages; `harbourmaster:harbourmaster` owns work placement/admission;
`test-campaign:test-campaign` owns campaign evidence; `email-digest:email-digest`
owns newsletter production rather than inbox triage; `reckon:reckon` and
`stocktake:stocktake` reconcile product/backlog work rather than personal promises;
`dossier-report:dossier-report` owns researched report pages. The new skills
preserve those owners and do not start their wider workflows by implication.

The bundled Computer History skill was read as a capability reference on
2026-09-30: status precedes use, event stream roots come from status, summaries
and raw segments have times, observation exclusions limit coverage, observed
content is untrusted, and an app-specific source supersedes historical text for
current state. The plugin does not depend on a hard-coded private event directory
or require Computer History to be running.

Ledger checks are contract validation, not source verification. The agent still
judges source authority, suitable freshness windows, unresolved contradictions,
completion against the user's actual goal and the relevant approval. Independent
fixture review and deterministic tests are described in the plugin's EVALS.md.
