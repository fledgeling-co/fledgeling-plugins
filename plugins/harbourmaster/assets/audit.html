Recommendation: ship master (icon.svg). Checks 1-4 verified on the real renders in audit-renders/. The squircle comes from the shared create-mac-icon/assets/squircle-path.txt, so the silhouette matches every sibling exactly; the tower is optically centred against the lit berth run; the 32px and 16px renders still read as a lit harbour light; one light model throughout, key above and left, with the contact shadow warm because the ground is warm. Ground and graphite values were lifted from the nautical siblings (ship-fleet, shipyard, ship-feature), which sampled the macOS 26 corpus rather than assuming them. Distinct from all three: they are horizontal, ground-level and lit from outside, this is the only vertical mass in the set and the only one that emits. Decorative icon, not an Icon Composer package — the material is in the file because nothing downstream will add it. Known liabilities to revisit: the quay is a flat gradient with no grain, so it reads slightly synthetic against corpus grounds; the two unlit berth marks fall below 8px at the 32px render and merge into the quay, so the lit/unlit contrast is a large-size reading only; Engine B (Arrow) and Engine C (raster) were not run, so the material was never scored against a diffusion reference and the fidelity loop did not run at all — three hand-authored takes is the documented substitution when the raster engines are not used, and it buys composition and legibility evidence but no material evidence.
Rubric: the 12-point icon audit from icon-directions.md (mask discipline, grid, silhouette, 16px identity, single light model, palette discipline, figure-ground, depth coherence, focal sizing, variant robustness, texture restraint, era fit) — checks 1–4 non-negotiable, delivery bar ≥10/12. Raster takes audited on their squircle-masked 1024 versions. Renders produced by `python3 ../scripts/audit_sheet.py render ` (1024 / 256 / 128 / 96 / 64 / 32 sources); verified by its `check` subcommand.
