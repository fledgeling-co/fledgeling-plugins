### 12. `kKJvsLV1mkw` — Kevin Powell — "Use new CSS without breaking anything"
~2 weeks old · ~25,700 views · 13:00 · human-written captions

- PLATFORM — Defines the three Baseline statuses precisely: **widely available** = in every browser engine for at least 30 months; **newly available** = in all engines but for under 30 months; **limited availability** = not yet in all three engines.
- PLATFORM — Warns Baseline is not a ship/don't-ship signal. Anchor positioning reads as unsupported in Baseline despite being in all browsers, because of differing spec states. Recommends Can I Use for the nuance, and notes many teams actually gate on the iOS version a feature shipped in, because vendor-locked old iPhones cannot update and every iOS browser is a WebKit skin.
- PLATFORM — States a model-specific hazard for AI-assisted CSS: some models reach for very old methods, using JavaScript for things CSS has done for years, while newer ones (names Opus 5.5) reach for features without sufficient support. Adds that Google's Modern Web Guidance skill is Baseline-based, which can make an agent think a feature is safer to ship than a given project needs.
- PLATFORM — CSS fails per-declaration rather than per-block, unlike JS, which is what makes progressive enhancement cheap. Names `text-wrap: pretty` as the safest kind of enhancement — nobody can tell when it is absent.
- PLATFORM — Names `interpolate-size: allow-keywords` as a bigger-stakes enhancement (height 0 → auto animation in one line, replacing JS), noting it is still Chrome-only at time of recording.
- PLATFORM — Two-declaration fallback pattern for colour: hex first, OKLCH second; the cascade takes the second if understood. Notes PostCSS and Lightning CSS can do this automatically.
- PLATFORM — `@supports` ("feature queries") techniques: redeclare a custom property inside an `@supports` block (credits Josh Comeau) so a `linear()` easing falls back to `cubic-bezier` without duplicating every rule — and stresses `@supports` is *required* for custom properties because any value is "valid" in a custom property. Also covers `@supports selector(...)`, which he says has good support.
- PLATFORM — Names features he judges still too early to ship: `sibling-index()` / `sibling-count()`, `@scope`; notes `@layer` has only recently come around.

### 13. `Ssm0vJtJr2U` — Syntax — "8 New CSS, JS and HTML Features You Should Know"
~2 months old · ~36,100 views · 18:38

- PLATFORM/COLOUR — Relative-colour alpha shorthand: `color / <percentage>` to make any colour semi-transparent at runtime (what Sass/Stylus did at build time). In Chrome since v151 (27 July 2026), Firefox nightly, Safari 27.
- PLATFORM — `progress()` function: returns a unitless value for how far a value sits between a start and an end, and the three values need not share a unit (e.g. where 2em sits between 8px and 100%). Unrelated to the HTML `<progress>` element. In everything except Firefox, which has filed intent to ship.
- PLATFORM — `Promise.allKeyed` (JS): pass an object whose properties are promises and await the object, destructuring resolved values by key instead of indexing into an array.
- PLATFORM — New declarative `<camera>` and `<microphone>` HTML elements, in prototyping. Both hosts are sceptical: you still need JS to handle the stream and the permission events, so the benefit is unclear unless it composes with the invokers API.
- PLATFORM — `attr()` upgraded: previously usable only with `content`, now usable for background, width, height and other properties — effectively CSS props passed as HTML attributes (e.g. `data-size="small|medium|large"` driving component styling). Everywhere but Firefox, which has intent to ship.
- PLATFORM/LAYOUT — `sibling-index()` and `sibling-count()`: compute per-item values (e.g. the rotation angle to space N items evenly around a circle) without JS or an nth-child ladder. Firefox has now shipped; in Safari for nearly a year.
- PLATFORM/LAYOUT — `max-content-sizing: shrink-to-fit`: lets a parent shrink to the size of a `fit-content` child, which previously required floats or hacks.
- PLATFORM/TYPE — `text-box-trim` / `text-box-edge`: trims the font's ascender/descender space so vertical centring in buttons actually looks centred. Example given: `text-box-trim: cap alphabetic` on an "ADMIT ONE" label, which then takes equal top and bottom padding. In Chrome since February 2025; everywhere but Firefox, which is at intent-to-prototype. Both hosts call it safe to adopt now as a progressive enhancement.

~2 months old · ~309,000 views · 10:33 · human-written captions

- PLATFORM — Contrast with Material Design: Google created depth with solid layers and shadows, keeping the actual content behind a surface out of view, so depth stays under the designer's control.

Framed as close to Microsoft's Windows 11 compromise but continuous rather than fixed.
- VISUAL — Summary formulation worth quoting in a skill: the glass does not disappear, the information beneath it does — optically complex, informationally simpler.

## Disagreements

**Mascots: current trend or slop signal?** Grayson's Graphics names "cute morphism" as trend #2 for 2027 and reads AI-company mascots (ChatGPT dots, Meta Muse, Grok Bot, Notion Nosy) as a deliberate trust-building move worth copying. Made By Chip lists "generic AI mascot with no brand story" on his 60-second AI-slop cheat sheet. The reconciling clause is "with no brand story", but the two still point in opposite directions for a designer deciding whether to add one.

**Motion: cut it, or is it the whole differentiator?** Sam Crawford would "skip one version" entirely and treats motion as a conversion risk on any ordinary business site. dreadjordan argues the opposite — that tasteful reaction to every action (his benchmark is *osu!*) is precisely the last 10% that separates real products from slop, and that an app that ignores your input is a failure. Kittl prescribes motion treatments for all ten of its trends. Ben Marriott's entire selection is motion-led work winning attention. The distinction is page-type: Crawford is talking about conversion pages, dreadjordan about app interaction, Marriott about brand film — but none of them says so.

**Does the website still matter?** Wes McDowell predicts a 30-page site collapsing to one landing page, with discovery and trust both living on YouTube. Jennie Lakenan keeps the site central and argues the fix is story and symbolism inside it. Sam Crawford keeps it central too and says clients are scrutinising its commercial performance harder than ever. These are not compatible as planning assumptions.

**Is minimalism dead?** Grayson's Graphics states flat design is "already long gone" and builds trend #1 on being its opposite. Jennie Lakenan presents an "almost shockingly minimal" site as the correct answer for one audience and says the best-converting sites are often plain and a little boring to look at. Kittl sits with Grayson's ("after years and years of clean white space minimalism").

**How durable is the list of AI tells?** Jennie Lakenan is explicit that the list expires — several of the 30-year veterans she polled said these are just the latest fads, every model update reshuffles them, and the purple gradient is already dating itself. Griffin Wooldridge and Made By Chip present their lists as stable checklists. Kenny Gunderman's reporting supports Lakenan: push a model off purple and Inter and it converges on Space Grotesk instead.

**Can a model get you to a genuinely distinctive result?** dreadjordan says yes — the last 10% is reachable, it just costs a lot of time, tokens and luck ("pulling the slot machine"). Jennie Lakenan says the gap is categorical, not effort-based: "execution is a solved problem, conception is not", and the hoop-crop and hand-drawn-icon examples are things a prompt could execute but would not propose. Made By Chip sits between them: the gap is real but closable by *supplying* the conception as a design system up front.

**Where does transparency belong on Apple platforms?** Design Lovers reads iOS 27 as making transparency a continuously-tuned variable across all surfaces — a refinement that keeps the glass everywhere but varies what shows through. Bitrig reads Apple's guidance as a hard role split — glass on the control layer, never the content layer. Compatible in principle, but they give a designer different defaults for a content card.
