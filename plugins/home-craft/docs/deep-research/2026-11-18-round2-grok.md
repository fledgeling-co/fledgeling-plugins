## Detailed Findings

### How should a native Swift/SwiftUI team ship CarPlay and HomeView?

Pick the category from the product’s primary job, request that one entitlement at [developer.apple.com/carplay](https://developer.apple.com/carplay/), and add a CarPlay scene to the existing SwiftUI app. Audio is the path if people listen. Video is the path if people watch, and it is the one that shows up on HomeView even when no car has enabled video-in-car. Voice-based conversation is a CarPlay category from iOS 26.4 and is not a HomeView category in any Apple document as of 18 November 2026. Widgets are a second, independent surface: a `systemSmall` widget can appear without any CarPlay entitlement.

<INFERENCE from="October 2026 guide footnote *2, DTS forum reply October 2026, HomeView support notes 16 November 2026">HomeView third-party software is a paired-device projection of an already-entitled CarPlay audio or video app, plus small widgets. A SwiftUI team does not create a HomeView target, a second app, or a HomeView-specific UI.</INFERENCE>

#### 3. Code

These skeletons follow the guide’s scene delegate, list, and now-playing samples, and the iOS 27 symbols `CPPlaybackConfiguration` and `CPSessionConfiguration.supportsVideoPlayback` (the latter is marked iOS 26.4). They were not compiled in this session.

Swift 6: CarPlay template types are `@MainActor`. `CPTemplateApplicationSceneDelegate` therefore lives on a `@MainActor` `NSObject`. `MPRemoteCommandCenter` handlers are nonisolated. Hop to the main actor before touching a template or the audio engine, and treat `.success` returned before that hop as “command accepted,” not “playback has started.” A CarPlay-only cold launch never creates the SwiftUI window, so playback setup belongs in `didConnect`, which the guide states directly.

Dynamic scene configuration is the SwiftUI path. A static `UIApplicationSceneManifest` that omits the window role can replace the `WindowGroup`. The guide allows either a manifest or a dynamic configuration.

**(a) Audio app**

```swift
import AVFoundation
import CarPlay
import MediaPlayer
import SwiftUI

@main
struct StudioApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) private var appDelegate
    var body: some Scene { WindowGroup { ContentView() } }
}

final class AppDelegate: NSObject, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        configurationForConnecting connectingSceneSession: UISceneSession,
        options: UIScene.ConnectionOptions
    ) -> UISceneConfiguration {
        // Role string from the CarPlay Developer Guide, 13 October 2026.
        if connectingSceneSession.role.rawValue == "CPTemplateApplicationSceneSessionRoleApplication" {
            let configuration = UISceneConfiguration(
                name: "CarPlay",
                sessionRole: connectingSceneSession.role
            )
            configuration.sceneClass = CPTemplateApplicationScene.self
            configuration.delegateClass = AudioCarPlaySceneDelegate.self
            return configuration
        }
        return UISceneConfiguration(name: nil, sessionRole: connectingSceneSession.role)
    }
}

@MainActor
final class AudioCarPlaySceneDelegate: UIResponder, CPTemplateApplicationSceneDelegate {
    private var interfaceController: CPInterfaceController?
    private let player = AVPlayer()

    func templateApplicationScene(
        _ scene: CPTemplateApplicationScene,
        didConnect interfaceController: CPInterfaceController
    ) {
        self.interfaceController = interfaceController
        installRemoteCommands()
        CPNowPlayingTemplate.shared.updateNowPlayingButtons([
            CPNowPlayingPlaybackRateButton { [weak self] _ in
                Task { @MainActor in self?.cycleRate() }
            }
        ])
        let item = CPListItem(text: "Latest episode", detailText: "Show")
        item.handler = { [weak self] _, completion in
            Task { @MainActor in
                self?.startPlayback()
                completion()
            }
        }
        let list = CPListTemplate(title: "Library", sections: [CPListSection(items: [item])])
        try? interfaceController.setRootTemplate(list, animated: true)
    }

    func templateApplicationScene(
        _ scene: CPTemplateApplicationScene,
        didDisconnectInterfaceController interfaceController: CPInterfaceController
    ) {
        self.interfaceController = nil
    }

    private func startPlayback() {
        let session = AVAudioSession.sharedInstance()
        try? session.setCategory(.playback, mode: .default)
        try? session.setActive(true)
        // Activate here, when playback starts, not in didConnect.
        player.play()
        MPNowPlayingInfoCenter.default().nowPlayingInfo = [
            MPMediaItemPropertyTitle: "Latest episode",
            MPNowPlayingInfoPropertyPlaybackRate: 1.0
        ]
        MPNowPlayingInfoCenter.default().playbackState = .playing
    }

    private func cycleRate() {
        let next: Float = player.rate == 1 ? 1.5 : 1
        player.rate = next
    }

    private func installRemoteCommands() {
        let center = MPRemoteCommandCenter.shared()
        center.playCommand.addTarget { [weak self] _ in
            Task { @MainActor in self?.startPlayback() }
            return .success
        }
        center.pauseCommand.addTarget { [weak self] _ in
            Task { @MainActor in
                self?.player.pause()
                MPNowPlayingInfoCenter.default().playbackState = .paused
            }
            return .success
        }
    }
}
```

#### 4. Entitlements and deployment

1. Apply at the CarPlay contact form. State one category. Agree to the CarPlay Entitlement Addendum. Apple grants each profile separately and can refuse or revoke it. [developer.apple.com](https://developer.apple.com/contact/request/download/CarPlay.pdf)
2. After approval, enable the capability on the App ID under Certificates, Identifiers & Profiles. The entitlements article calls this managed capabilities, on the Additional Capabilities tab. [developer.apple.com](https://developer.apple.com/documentation/carplay/requesting-carplay-entitlements)
3. Regenerate development, Ad Hoc, and App Store profiles. The guide says Xcode and Simulator need a profile that contains the entitlement.
4. Add the Boolean key to the target entitlements file. Turn off automatic signing if the profile must be the one you just generated, and set Code Signing Entitlements to that file. The article’s table lists only audio, communication, charging, maps, parking, and quick ordering. The 13 October guide is the complete key list, including fueling, driving task, public safety, video, and voice.
5. Once the key is in a shipping build, the icon appears for everyone. The guide says you cannot show CarPlay to a subset of users. Ship the CarPlay scene only when it is ready.
6. App Review: the guidelines introduction cites CarPlay Audio as a limited entitlement. Reviewers also apply the guide and the addendum. Provide a demo account, and in the review notes say which category you hold and that CarPlay was tested in Device Hub and on a head unit. No HomeView review, opt-in, or Info.plist key appears in the guide, the HIG, or the DTS reply. DTS said to keep the iPhone as the supported destination. [developer.apple.com](https://developer.apple.com/forums/thread/850841)

#### 7. The six open questions

**(a) Can one app hold both audio and video?**

<CONFLICTING_EVIDENCE>Session 212, 8 June 2026, says to include both entitlements if the content is listened to and watched, so the icon still appears in cars without video-in-car. The guide dated 13 October 2026 says multiple categories cannot be combined, and that multiple entitlements may not be combined unless noted. The only note is EV charging plus fueling. Footnote *2 uses “or”: an audio app or a video app appears on HomeView. The video entitlement page, current as of 10 November 2026, says that key cannot be used to play audio-only content. The audio category description still says an audio app may offer “a mixture of audio and video playback,” and an audio app that does so must support AirPlay.</CONFLICTING_EVIDENCE>

The later written guide is the document that matches the entitlement keys App Review can see. Session 212 is earlier and was not edited when the guide was. A September 2026 forum report, indexed on the CarPlay tag, says adding `carplay-video` to an app that worked with `carplay-audio` produced a blank screen and no scene callbacks. That report is unanswered, and a car or simulator without video-in-car is an alternative explanation, because video apps are hidden when the vehicle cannot play video. [developer.apple.com](https://developer.apple.com/forums/tags/carplay?page=2)

Decision: one key per target. Audio plus AirPlay covers listened-to video inside the audio rules. Video covers HomeView and parked cars that enable video-in-car. Two apps if you truly need both icons. Ask in the entitlement request which document governs, and keep the answer.

**(b) Does `disfavoredLocations([.carPlay])` hide the widget on HomeView?**

Apple has not said. The modifier’s only car case is `.carPlay`. `WidgetLocation` has no HomeView case. §6.4.1 says to use `disfavoredLocations` when a widget is unfit for CarPlay, in the same section that allows the widget on HomeView. <INFERENCE from="WidgetLocation case list and the 6.4.1 wording">There is no API to target HomeView separately. Whether `.carPlay` also suppresses HomeView is unstated and has to be checked on hardware.</INFERENCE> [developer.apple.com](https://developer.apple.com/documentation/widgetkit/widgetlocation/carplay)

**(c) Public safety and navigation templates, iOS 26 versus iOS 27.**

From the 13 October 2026 matrix. The version split is the footnotes, not a second table.

Public safety, both releases: action sheet, alert, grid, list, tab bar, contact, information, now playing, point of interest. iOS 27 adds voice control and search. No map template. Depth 5.

Navigation, both releases: action sheet, alert, grid, list, tab bar, voice control, contact, information, map, plus the base map window, dashboard scene, and instrument-cluster scene. iOS 27 adds panels. Route sharing needs iOS 26.4 and a supported car. No now playing, no point of interest. Search is the one cell whose column is easy to misread in a text extract. The extract shows a search bullet on the navigation column with no iOS 27 footnote. Confirm that cell against the PDF table before relying on a navigation search template. Depth 5.

**(d) Can `CPVoiceControlTemplate` be the root on iOS 26.4 or later?**

The guide requires some root, and its sample root is a `CPListTemplate`. It also requires the voice-control screen to be visible whenever voice is active, and it lists that template for the voice category from iOS 26.4. It never says the voice template is forbidden as the root. Navigation’s older pattern is to present it. iOS 27 adds an overlay presentation, which assumes some other template is underneath. <MISSING_DATA>An Apple sentence that allows or forbids `setRootTemplate(CPVoiceControlTemplate)` was sought and is not in the guide or on the symbol page.</MISSING_DATA> Ship a list root if you want the path the sample shows. Try the voice template as root in Device Hub. The documented failure is a runtime exception for an unsupported template, in which case present the voice template over the list.

**(e) Do arbitrary third-party Live Activities appear on HomeView?**

On CarPlay, yes, from iOS 26, for any app that supports the small activity family. On HomeView, Apple has not said so. The guide’s Live Activities section names CarPlay and CarPlay Ultra. The quoted §6.4 text names widgets and CarPlay apps, not Live Activities. The 27.2 HomeView release notes do not mention third-party Live Activities. [developer.apple.com](https://developer.apple.com/download/files/CarPlay-Developer-Guide.pdf)

**(f) Maximum navigation depth for video apps.**

Not stated. The depth paragraph gives audio 5 templates, including the root, and does not mention video. Video shares the “Audio, video” template column, and now playing still allows only a list pushed on top. <INFERENCE from="the shared template column and the audio depth sentence">Five, including the root, is the figure to design to, and it is an inference. The guide does not write it down.</INFERENCE>

### What is the current state, and what is the strongest evidence?

The strongest evidence is the CarPlay Developer Guide PDF downloaded from Apple on 18 November 2026, with the footer date 13 October 2026, plus the CarPlay HIG, the video entitlement page, WWDC26 session 212, and Apple’s HomeView newsroom and support notes from 12–16 November 2026.

State as of 18 November 2026: eleven CarPlay categories, video new in iOS 27, voice new in iOS 26.4, HomeView on sale and showing audio and video CarPlay apps from a paired iPhone or iPad, widgets allowed by contract onto HomeView, no public HomeView SDK. The 27.3 beta contains private strings for a conversational-apps category on the HomeView bridge and does not expose them.

### What are the contrasting viewpoints?

Session 212 and the October guide disagree on combining audio and video, as open question (a) lays out. A May 2026 developer report says the portal issued a second entitlement the guide forbids. A September 2026 report says audio plus video yielded a blank scene. Those three can all be true: the talk recommended it, the later guide forbids it, the portal sometimes issues a second key, and the runtime may not connect.

The entitlements article still tells you to open CarPlay from the iOS Simulator’s I/O menu. The October guide tells you to use Device Hub and a USB iPhone. Developers report the iOS 27 simulator display black. Both documents are Apple’s. The guide is the one that names Xcode 27.

DPLA §6.4.2 is broader than the marketing line “audio and video.” The documentation then narrows it back to those two. A future documentation edit could add voice without an agreement change. That is why the 27.3 string matters, and why it is not a category you can ship.

### What changed recently, and what is the trajectory?

From WWDC25 (June 2025) through this month, CarPlay gained widgets and Live Activities, then a voice category, then video, a voice overlay, and richer lists. HomeView, announced alongside the 13 October agreement change and on sale 13 November, reused the audio and video entitlements instead of opening a platform. The 27.3 beta diff is the first sign that a third category, conversational apps, is being wired into that bridge, with the voice template still gated on “remote device control.”

<INFERENCE from="the October guide’s HomeView footnote, the DTS reply, and the unfinished 27.3 strings">The near-term trajectory is more CarPlay categories becoming eligible for projection, not a HomeView SDK. Build the CarPlay scene. Re-read the guide’s HomeView footnote when iOS 27.3 ships, before promising voice on the display.</INFERENCE>
