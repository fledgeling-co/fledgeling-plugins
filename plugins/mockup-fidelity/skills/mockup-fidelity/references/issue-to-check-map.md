# Every miss → its mechanical check

**This file is the single home for detector rationale.** A threshold whose derivation has been dropped is a
number nobody can defend, so every check below keeps the incident and the measurement it came from.

A field log from a long Framer→StyleX clone. Each row is a real difference a human eye caught
that the differ (or the agent driving it) had reported as "matching". The rule the user set:
**the diff script is the objective measure — make it find every difference, no matter how complex.**
Every row below is now a check in `assets/diff/` (or a documented method), so the class can't recur.

> **Reading the "where" column.** Rows name the pipeline as it stood when the miss was logged, so many say
> `extract-mock.js` / `diff.mjs` / `structure-diff.mjs`. **Those three files no longer exist.** One
> injectable, `assets/diff/analyze.js`, ports every one of their detectors — capture in MODE A, comparison
> in MODE B — and `assets/diff/capture.mjs` is the harness that injects it. Read "captured in
> `extract-mock.js`" as MODE A and "compared in `diff.mjs`/`structure-diff.mjs`" as MODE B; the version
> stamps are kept because they date the derivation.

> **Nine of the classes below cannot be measured in the current engine at all** — shadow, gradient (the CSS
> half), text-transform, transition, animation, flex shorthand, pseudo-elements, `::placeholder`, and SVG
> glyph extent. A runtime preflight switches each off and reports `available:false` with a verbatim reason
> rather than agreeing, so a row here can be a real, implemented check that still returns nothing on this
> engine. Which ones, why, and what remains readable:
> [`engine-capability-matrix.md`](./engine-capability-matrix.md). Two consequences worth carrying into every
> row you read: **pseudo-element measurement is REFUSED rather than unavailable** (the pseudo argument is
> ignored and the element's own style comes back, so reading it would fold the element's own border in as if
> the pseudo drew it), and **the icon-glyph and trailing-arrow checks fall back to svg PRESENCE and are
> labelled presence-only** (`getBBox()` returns an all-zero rect without throwing, so a MISSING arrow is
> caught and a wrong-size or swapped glyph is not).

viewport I measured, but wrong" remained: what the UI does on **hover/focus** (a state the static
dump can never enter), and what it does at **other widths** (a single 1280 capture is blind to the
mobile layout and to whether the breakpoint TRANSITIONS even agree). v2.0.0 adds both to
`assets/diff/analyze.js`. Both capture in MODE A and compare in MODE B; both dedup a repeating root
cause to a few rows + a `[×N]` summary.

and whether the named family APPLIES (DOM-span, not fallback). A real homepage bug passed ALL of them and

DOM-span probe (#20) cannot see, because it is about a feature's GLYPH, not the family.

## v2.2.0 — the FONT-METRIC / VERSION detector

The v2.1.0 self-check catches a feature's GLYPH being stripped (same width, wrong letterform). A sibling
class is the opposite: the SAME family at the SAME size renders to a CONSISTENTLY different WIDTH because the
two sides ship a DIFFERENT VERSION of the font. Unlike cv11 this IS a width difference — so it is directly
measurable, and it is the ROOT CAUSE behind a height-differing line-count that the differ previously flagged
only as a symptom.

| # | What the differ was blind to | Why the prior checks missed it | The mechanical check (where) | Real diolog example |
|---|---|---|---|---|
| 32 | a homepage case-study body ("Beyond any single draft or reply…") with IDENTICAL declared font props on both sides — Inter, 18px, weight 400, letter-spacing −0.36px, line-height 27.9px, container width 507px — and the font APPLIES on both, yet LIVE wraps to 4 lines (height 112) while the TARGET wraps to 3 lines (height 84): "slightly larger on live" | every DECLARED-prop check matched (family/size/weight/letter-spacing identical) and the rendered-font DOM-span check said the family APPLIES on both, so nothing fired on the ROOT CAUSE. The height-aware line-count check flagged the SYMPTOM (4 lines/112 vs 3 lines/84) but never surfaced WHY: the exact text renders 636px on live vs 625px on target — the target self-hosted a DIFFERENT VERSION of Inter (rsms v4, ~1.8% NARROWER than live's Google Inter v20) at the same size. The actionable signal is "same family + size, consistently different rendered WIDTH ⇒ different font version/metrics", which — unlike cv11 (#31, same-width letterform) — IS a width difference and so is directly measurable in-page | **FONT-METRIC / VERSION check** — `analyze.js` `capture()` records each text node's EXACT-TEXT WIDTH (`exactW`): the node's own text (capped ~80 chars) laid out nowrap in an offscreen span using the element's EXACT computed font (family, weight, style, size, letter-spacing, word-spacing, font-feature-settings). MODE B, per MATCHED text element where the SAME first font-family applies on BOTH sides, computes the width RATIO target/reference and accumulates it per family. ## The standing principles these encode

1. **Reference the LIVE rendered site, never a re-served scrape** (#6). A runtime-hydrated framework resolves a different variant off-origin. This alone caused several "I matched it exactly but it's wrong".
2. **`getComputedStyle(element)` is blind to pseudo-elements and to non-CSS layers** (#9, #10). Fold pseudo borders/shadows; capture media-layer children.
3. **Computed style can match while the RENDER differs** — wrong glyph variant (cv11), variable-vs-static synthesis (#13), font-version width (#2), wrap balance (#5). Always carry **rendered geometry** (w/h/center-x), **glyph extent**, **line-count**, and **loaded faces** as ground truth, not just declared properties.
4. **Compare the SAME content on the SAME element type** (#7, #12). A node-boundary mismatch (dash-in-text, text-node-vs-button) makes a width/size comparison meaningless — pair to the styled box and slice to the same string.
5. **Gaps live between elements, not only inside boxes** (#11, #15). Check sibling gaps and spacing accumulation, not just each box's own padding.
6. **When the human eye and a measurement disagree, the eye wins — go LOOK / inspect the live element** (#9 was solved by the user reading `--border-color` in devtools). A confident wrong number is worse than no number; the fix is a better measurement, on the right node.
7. **Text-pairing alone is blind to NON-TEXT containers and to MISPAIRED repeated text** (#16, #19, #22, #17). A differ that only style-checks elements it matched BY TEXT never reaches a section/card/divider with no text of its own — so ALSO match containers STRUCTURALLY (path → geometry fallback) and compare their bg, full-bleed media layer, border (all sides, incl. `::after`), radius, shadow, and a page-wide hairline. And when the probe text is non-unique, DISAMBIGUATE by position before comparing, or every instance pairs to the first.
8. **`document.fonts.check` is necessary but NOT sufficient for "is the named face actually rendering"** (#20). A face can register as loaded yet not serve glyphs to rendered text (declared-vs-rendered drift). **The ground truth is a RENDERED-DOM metric, and it must be measured with a real DOM `<span>`, NOT canvas `measureText`** (v2.0.2). Canvas ignores `unicode-range` subsetting and does not replicate the browser's DOM font-matching cascade, so it cannot see a DOM-level fallback. Lay out a hidden span of a probe string twice — `'<Named>', <generic>` vs bare `<generic>` — for the same weight/style/size, against TWO distinct generics (monospace + serif); if the named width collapses to BOTH fallback baselines, the named family fell straight through to the fallback (`applies:false`). Await `document.fonts.ready` before probing. Compare the two SIDES' `applies` flags — flag only a disagreement, never a per-node absolute.
9. **An illustration's placeholder CONTENT is noise, but its POSITION (#21) and its STYLING (#33) are defect classes** (#21, #33). A product mockup's fake tickers/numbers legitimately differ, so suppress the TEXT-content comparison for them — but DON'T drop the whole subtree. Compare the illustration's geometry RELATIVE to a stable section anchor (#21), AND compare its internals' COMPUTED STYLE (#33: border incl. `::after`, radius, shadow, bg/colour, letter-spacing, font, padding, geometry), pairing internals by POSITION/STRUCTURE since their text is placeholder. Suppress only the STRING; never the style.
10. **A DECLARED + APPLIED OpenType feature can still have NO EFFECT — only the rendered glyph SHAPE proves it took** (#31). `font-feature-settings:"cv11"` matching, the family applying (not a fallback), and the controlled span width being identical are ALL necessary but NOT sufficient: a subset woff2 that stripped the cvXX/ssXX glyph renders the default letterform at the SAME width, so every width / DOM-span / glyph-extent check is blind. The ground truth is a glyph-SHAPE comparison — render the probe WITH vs WITHOUT the requested feature and pixel-compare; identical ⇒ ineffective. Pick the rasteriser by capability TEST (`'fontFeatureSettings' in ctx` → in-page canvas; else a runner screenshot + pixel-diff of probe pairs), never by assumption. Compare the two SIDES' effectiveness — escalate when the reference's feature takes and the target's does not — and emit an honest "unresolved" note rather than a silent pass.
11. **The SAME font family at the SAME size can render to a CONSISTENTLY different WIDTH — that is a different font VERSION, and unlike a glyph variant it IS measurable** (#32). When every declared font prop matches and the family applies on both sides, but a block "looks slightly larger on live" / wraps to a different line count, the root cause is usually a font-VERSION mismatch (the target self-hosts rsms Inter v4 ≈1.8% narrower than live's Google Inter v20 at the same size). Measure the EXACT text laid out nowrap in the element's exact computed font (family/weight/style/size/letter-spacing/word-spacing/feature-settings) on BOTH sides, take the width RATIO target/reference, and AGGREGATE per family — a version mismatch is UNIFORM across the family, so the median ratio is a clean, low-noise signal; emit ONE finding per family above a small tolerance (0.7%, with a ≥70%-same-direction guard), never per element. The width-differing line-count is the SYMPTOM (a height-differing line-count is a REAL wrap divergence — emit it confident/HIGH with the height delta, never bucket it as span-split noise); the width-ratio is the actionable root cause (swap to the matching font version). Contrast #31: a cvXX glyph stripped from a subset is the SAME width, so only the glyph SHAPE reveals it; a font-version drift IS a width difference, so it is measured directly.
12. **A noise exclusion must be NARROW — drop only the noisy dimension, never the whole node** (#33). The illustration-internal exclusion was introduced (#21) to stop a flood on placeholder mockup CONTENT, but it dropped illustration internals ENTIRELY, so their real STYLING (a card border, a row label's letter-spacing) went unchecked and real defects shipped. The correct shape of a content-noise exclusion is a SPLIT: suppress only the placeholder TEXT-content comparison (route it to `noiseExcluded`), while STILL comparing the COMPUTED STYLE / box / geometry of the same nodes. When the text is placeholder it can't be used to pair — pair the internals by POSITION/STRUCTURE instead — and keep the dedup discipline (repeated identical mockup-row styles collapse to a few rows + a `[×N]` summary) so the restored coverage doesn't flood. Before widening any "exclude as noise" rule, ask which DIMENSION is actually noisy (here: the string) and exclude only that.
13. **An element can MOVE without resizing, and a PARENT-level diff is not a substitute for a PER-ELEMENT one** (#34). A status/badge that shifts down because its parent's `align-items` changed (same size) was caught only as the parent's `align-items` diff — which doesn't name the visibly-misplaced child. Carry a per-element vertical-offset detector that measures each matched element's top RELATIVE TO ITS DIRECT PARENT on both sides and fires when the offset differs at the SAME size (a PURE move). Guard the noise: require both the element's own w&h to match (else it's a reflow, a different class) and both parents to pair; DEDUP per `(parent\|delta)` because a whole column shifting by one amount is ONE alignment change, not N defects.
14. **Gaps between BLOCK containers live in margin/padding, not just flex/grid `gap` or text pairs** (#35). The text-driven `gap→/←-sibling` only reaches text-paired nodes, and the layout detector only compares flex/grid `gap` — so block-flow spacing between non-text block boxes (a divided point list, stacked cards) was invisible. Measure the gap from rendered geometry (`next.top − this.bottom`, which INCLUDES margin/padding/margin-collapse) between PAIRED block containers and their next sibling, on both sides; only when both boxes pair to the SAME pair on each side. Block-flow spacing is a first-class gap class, not a flex/grid-only one.
15. **A line-height is a precise VALUE — compare the value, not a loose height proxy** (#36). The line-height check used a `max(2, 0.12·fs)` floor (a tolerance sized for a noisy non-text height) which swallowed a real 0.75px label delta. But the resolved line-height px IS a precise computed number, so compare the VALUE on both sides (resolving each `normal`→~1.2×fs) with a tight ~0.6px tolerance — a sub-2px-but-real line-height drift is a defect. And every STYLE pass that compares font props (including the illustration-internal one) must include line-height; an omitted property is an unconditional blind spot, not a tolerance question.
16. **For "is the right typeface ACTUALLY applied", the engine's per-node rendered face is the truth — and an engine that loads no fonts cannot give it to you** (#37). `getComputedStyle` reports the declared family (Inter first on both), `document.fonts.check` passes on both, and even the DOM-span apply/fallback probe (#20) measures a *probe string*, not the node's real face resolution — so a node that declares Inter but renders the system fallback passes all three. The answer used to be `CSS.getPlatformFontsForNode`, which returns what the renderer actually rasterised for THAT node. Under Obscura it returns nothing, and no substitute exists at any level: no web font is ever loaded, so both sides genuinely render the same fallback and every font check honestly agrees. The generalisable rule is the one that survives: **a check whose "pass" and "cannot run" look identical must report which one it is.** The harness now records the layer as `available:false` with a reason rather than a zero, and the typeface question moves to a real browser.
17. **A SCREENSHOT-class difference must be caught BY THE TOOL — a missing decorative child passes every DOM diff because both element BOXES exist** (#38). The structure diff matches an element when both boxes exist; a trailing → svg, a hairline divider, or an icon the target omits INSIDE a matched element is invisible to it. Crop each PAIRED element from both full-page screenshots and `odiff` the crops: a **same-size box with a high pixel-diff and no other finding** is a rendering anomaly (a missing decorative child / occlusion / paint difference) — the diff crop is the TRIGGER to add what's missing. A raster % is never a verdict on its own; the tool must SURFACE the visual difference so the human/agent inspects it, rather than concluding "matches" from a green DOM diff. Suppress text-edge noise with `antialiasing:true` + a threshold; classify size-mismatch raster diffs as CORROBORATION of a geometry finding, not a new defect.
18. **A text-less node is still a node — pair it by GEOMETRY (IoU) so it can be presence/raster-checked** (#39). `analyze.js` pairs by text → structural path; a bare svg/icon/decorative div has no text and falls into the unpaired pool, never checked. After text/structure pairing, pair the remaining text-less nodes across sides by bbox Intersection-over-Union ≥ 0.9 — a high IoU is a confident "same element in the same place", low false-positive — so an arrow/icon becomes a candidate the raster + presence layers evaluate. Capture `getBoundingClientRect` for EVERY node so this pairing has the rects it needs.
20. **"Same font, different declared SHAPING" is its own class — a DECLARED property changes the render without changing which file LOADS** (#41–#43). Three declared typographic properties slip every font-class layer AT ONCE, so each needs a deterministic declared-value comparison, not a rendered measurement: `font-feature-settings` (a `cvXX`/`ssXX` character-variant — the `cv11` single-vs-double-story `a`), `font-variation-settings` (a `wght`/`opsz`/`slnt` axis applied on one side only), and the FULL `font-family` DECLARATION (same KIND, different cascade — `'Inter', system-ui, …, sans-serif` vs `Inter, sans-serif`). They all pass: the family-KIND check (#1170) only compares serif/sans/mono; CDP `getPlatformFontsForNode` (#37) reports the SAME font FILE because a variant glyph or axis is WITHIN the file; and the odiff raster (#38) runs `antialiasing:true`, so a glyph-edge variant looks like font-smoothing noise and is suppressed. Distinguish this from #31: there a feature was DECLARED IDENTICALLY but a subset font STRIPPED its glyph (same width → needs a glyph-SHAPE raster to prove ineffectiveness); here the two sides DECLARE a DIFFERENT value, so a normalised string comparison of the declared computed value is exact and deterministic. Normalise before comparing (lowercase, strip/normalise quotes, sort the order-irrelevant comma list, collapse whitespace, `''`→`normal`) so a reordered or requoted but equivalent declaration does NOT false-positive. And because all three are almost always set SITE-WIDE, DEDUP per `(property|normTarget|normRef)` to ONE root-cause finding + a `[×N elements]` count — never a per-element flood. The pseudo-border handling was either a NARROW fold (copy a pseudo border into `comp` only when the element has none) or scoped to illustration internals (#33) — so a `::after { border/background/box-shadow }` overlay that DIFFERS across sides, or is present on one side only, on an ordinary element went unchecked. Extract `getComputedStyle(el,'::before'|'::after')` box properties for EVERY paired element and compare them universally (presence, border, background/-image, box-shadow, radius); dedup a repeating pseudo defect (every card's `::after` border) to a few rows + a `[×N]` summary. A property the renderer draws (a pseudo overlay) is a first-class style class, not an illustration-only or fold-only special case.
21. **Over-reporting spends the same trust as under-reporting, so a HEURISTIC detector must be CORROBORATED before it fires, and a suppression must be a BUCKET rather than a deletion** (#45–#47). A per-node heuristic used as an absolute flooded ~92 % of text nodes on pages where the font was fine; the fix was to require a second, independent signal AND a cross-side disagreement before emitting, and to suppress whenever the positive evidence is present. Two rules generalise: **compare the two SIDES, never a per-node absolute** (a detector that can fire on one side alone is measuring the engine, not the difference), and **route confident noise into a named `noiseExcluded` bucket** so it is inspectable and countable — the moment it is deleted instead, nobody can tell an exclusion that is working from one that is hiding a defect (the same lesson as #12/#33, one level up).
22. **A score needs a curve and a DENOMINATOR** (#48). `100 − penalty` floored every full page at 0, which made the number useless for ranking or progress; `100 · e^(−penalty/900)` is monotonic and never hard-floors. But a curve is only half of it: a score is about the classes that actually ran, so it is reported WITH `scoreCovers` (probed / ran / silenced) and, when anything is silenced, a `scoreCaveat` sentence — because "84" printed beside nine unmeasured classes reads as "84 % right". Never quote the number without its denominator.
23. **A check that CANNOT RUN must say so, and a DEGRADED check must be LABELLED** — generalising #16 from the font class to every class. A runtime preflight probes the engine and switches off the nine classes it cannot measure, each reporting `available:false` with a verbatim reason; a pseudo read that returns a plausible WRONG value is **REFUSED** rather than merely unavailable; and where a check degrades to a weaker signal it says which — the icon and trailing-arrow checks fall back to svg PRESENCE and label their findings presence-only, so "arrow present" is never read as "arrow correct". The verdict is three-valued for the same reason: `capture.mjs --assert` returns **3 (inconclusive)** rather than 0, because "these differ" and "nobody asked" are different answers and only one of them is a pass. The measurements, dates and engine version live in [`engine-capability-matrix.md`](./engine-capability-matrix.md) — one home, so the next capability change is a single edit and not six diverging copies.
