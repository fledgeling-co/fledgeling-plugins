Evidence-dense scrollytelling · what measurably works

The scroll is settled.
The evidence for it isn’t.

Five independent deep-research runs were pointed at one question: how do newsroom graphics desks build single-page, evidence-dense scrollytelling reports, and what measurably works? They converge on a build spec none of them contradicts. They split on the one claim the form is usually sold on — that scrolling makes readers understand more.

The finding, before you scroll

The production form is not in dispute. All five runs land on the same architecture: an author-driven spine that opens into bounded exploration, one claim per scroll state, motion spent only on transitions between related states, claim-local citations backed by a persistent registry, a static document underneath everything, and a hard performance and accessibility floor.[1,2,29]

What is in dispute is whether any of it improves comprehension. The two largest controlled comparisons in the corpus — 454 and 240 participants — both found scrollytelling matched the formats it was tested against on comprehension while beating them on engagement, perceived clarity and cognitive load.[4,9] One run in the panel disagrees, and the disagreement is traceable to a single source that the other four never saw.

Read this as a build spec, not a case for the format. Everything below that survives all five runs is safe to encode. Everything in §11 is not.

01

The corpus

What a panel is for

A single deep-research run reads as consensus because there is nothing in the room to contradict it. Five runs on the same brief produce something a single run cannot: a record of where independent search paths agree, and a shorter, sharper record of where they do not. This page is built from that second record.

Overlap Of 170 dereferenceable source slots across the five lists, 154 are distinct URLs and only 13 appear in two or more runs. Mirrors inflate that — Segel & Heer’s 2010 paper appears in four lists under three different URLs — but after hand-reconciling the foundational papers the overlap still sits near a sixth. The three URLs cited by three or more runs are all specifications or library documentation, not research.

That last figure is the interesting one. The five runs reached broadly the same production rules from source bases that barely touch. Convergence under near-independence is a stronger signal than convergence under a shared reading list — and it is the reason the agreement matrix in §12 is worth reading before the prose.

Two properties of the corpus constrain what can be claimed here. Gemini’s list is the longest and the least checkable: 55 of its 77 entries are vertexaisearch…grounding-api-redirect URLs that cannot be dereferenced as citations, so several of its distinctive numbers cannot be traced to a publisher at all. And no run found a newsroom willing to publish step-level completion data for a real scrollytelling piece; the funnel that would settle the pacing question does not exist in public.[19]

02

Structure

The structure that holds

Every run starts in the same place, because there is only one place to start. Segel and Heer’s 2010 design-space analysis of 58 published narrative visualisations defines three structures on an author-driven to reader-driven axis: the martini glass, an authored stem that opens into a sandbox; the interactive slideshow, where interaction is admitted but bounded inside each stage; and the drill-down, a general theme whose instances the reader selects.[1] All five runs nominate the martini glass as the default for an evidence-dense report, and for the same reason: constrain the argument, then release to the data.

Martini glass as default is the only structural recommendation in the corpus that no run qualifies, hedges or contests.

COGPX All five runs

Under that taxonomy sits a production vocabulary. Oesch, Renner and Roth — then at Neue Zürcher Zeitung — analysed 50 published scrollytelling articles and grouped the fine-grained “scrollers” into five techniques: graphic sequences, animated transitions, panning and zooming, scrolling through movies, and show-and-autoplay.[2] Their stated motive was cost: scrollytelling is expensive to produce and a shared vocabulary lets teams implement it faster. The EU’s official Data Visualisation Guide has since adopted the taxonomy as public guidance.[3]

One idea per scroll state

The discipline every run repeats is not a research finding. It is a convergent production constraint, and it is worth saying so plainly: no controlled study in the corpus tests the phrase. What supports it is a stack of adjacent results. The ONS’s published editorial guidance says the format works best presenting one point at a time.[29] Bostock’s argument is mechanical — scrolling’s strength is linearity, one axis, no branching, the reader’s only decision being forward or backward.[23] The Pudding’s version is blunter: a few steps to make the point, then exit, because what feels fine on desktop becomes tiring on a small screen.[24] And Hullman et al.’s corpus analysis of 42 professional narrative visualisations found memory and preference benefits for sequences built on parallelism — repeated structural relationships that let readers compare adjacent states.[16]

Not a measured optimum Two runs flag this explicitly. No generalisable value was found for words per step, state count, viewport-heights per chapter or pin duration; topic complexity, device height and chart literacy confound any universal threshold. Treat “one idea per scroll state” as an editorial rule with converging support, not as a law.

The operational form the corpus supports is a state record rather than a word count. Each scroll state carries one claim identifier, one visual question and one stable end state; adjacent states reuse objects, scales and spatial positions unless changing one of those is the evidence; and if a state’s caption contains two independent propositions, the state splits. Crucially, every state must render directly and idempotently from its own identifier, because readers skip across states faster than animations complete.[26]

The other structural rule the corpus converges on is rhythm. A report alternates between ordinary document flow and bounded visual episodes; pinning the whole page permanently costs orientation, accessibility and mobile resilience.[30] The ONS builds exactly this way — a reusable component chassis for layout, navigation, charts and maps, with article-specific state connecting text to visuals, and pre-rendered HTML underneath for compatibility, JavaScript-disabled reading and indexing.[28]

03

Comprehension

The result nobody wanted

The format’s central promise is that readers understand and remember more. The measured record does not support it, and the failure is consistent across independent populations, materials and research groups.

Scrollytelling’s measured advantage is engagement, perceived clarity and reduced cognitive load. It is not comprehension.

COGPX Asserted by Claude, OpenAI and Codex · partial in Perplexity · contested by Gemini

The largest direct test put scrollytelling against plain text, two nutrition-label variants and a standalone interactive visualisation, N=454, between subjects. Comprehension accuracy and confidence were equivalent; cognitive load was lower and engagement, perceived clarity and willingness to adopt were higher than text; differences in perceived understanding, transparency and trust were small and statistically inconclusive.[4] The same visualisation shown without narrative scaffolding performed slightly worse, which is the paper’s strongest argument for narrative framing as such.

McKenna et al.’s 240-participant study of narrative flow found animated transitions beat static visuals on perceived engagement at p<.001, while comprehension averaged about four out of five with no major differences between conditions — and the scroller-versus-stepper comparison was inconclusive.[9] Zhi, Ottley and Metoyer, N=180, found the opposite of the expected direction: a slideshow layout produced better comprehension, while explicitly linking prose to the marks that support it raised engagement and improved recall.[10] Obie et al., N=40, found author narration improved value-message comprehension and short-term fact recall, both at p=.04, and neither long-term fact recall nor long-term value-message recall.[11]

Two further results bound the enthusiasm. Boy, Détienne and Fekete ran three web field experiments and found that adding an introductory story to an exploratory visualisation did not increase subsequent exploration at all; in two follow-ups only 40.9% and 41.5% of qualifying sessions traversed every narrative section linearly.[12] And Rogha et al. found contrasting narratives raised surprise and interest while raising recall error and leaving attitudes unchanged — engagement moving in the opposite direction to accuracy.[13]

Two large-scale results sit outside that plot and pull in the format’s favour. A meta-analysis across 75-plus samples and 33,000-plus participants finds narrative texts more easily understood and better recalled than expository ones, robust to single-study exclusion.[18] And Borkin et al., working across 393 visualisations with eye movements from 33 participants, found titles and supporting text materially aided recognition and recall, with recognisable objects appearing in 74% of the most recognisable third of visualisations and 8% of the least.[15] Neither is a result about scrolling. Narrative helps; annotation helps; the delivery mechanism is not what the evidence is about.

What this converts to

Do not report dwell time, completion or interaction counts as evidence of learning. Evaluate comprehension and delayed recall separately from engagement, because the corpus contains at least one study in which they move in opposite directions.[13,9]

04

Motion

Motion has a unit of analysis

The animation literature reads as a flat contradiction until you notice the two sides are animating different things. Every run in the panel finds both halves; four of them resolve it the same way.

On one side, Heer and Robertson’s two controlled experiments, N=24, found animated transitions significantly improved graphical perception, with advantages over static transitions for object tracking and value estimation. Their object-tracking animations ran 1.25 seconds and value-change animations 2 seconds; animated conditions reduced tracking error at p<0.001.[6] Their staging principle — animate scatter to bar by first moving points to their x-coordinates and updating the axis to form a dot plot, then morphing points into bars — is the most reused technique in the whole corpus.

On the other, Tversky, Morrison and Bétrancourt’s review of the learning literature concluded that where animated graphics appeared superior, scrutiny revealed a lack of equivalence: the animated condition conveyed more information or added interactivity. Presenting any graphic beat no instruction, but animated-condition students did not outperform equivalent text or static-graphic conditions — and after a week the text students’ performance improved while the animation students’ declined, attributed to deeper processing of text.[7] Robertson et al. add the analysis case: animated trend displays were enjoyable and fast for presentation but least effective for analysis, where static views were faster and small multiples more accurate.[8]

Animate between two states of one encoding. Do not animate to explain. The disagreement in the literature is not about whether animation works; it is about the unit being animated.

COGPX All five runs reach this resolution

Heer and Robertson also bound their own result, and this is the part the popular reading drops. More staging was not monotonically better: extreme staging was worse than direct animation for donut-chart value changes at p=0.024, and stacked bars showed no significant animation effect at all, p=0.224.[6] Axis rescaling increased errors and “unknown” responses; retaining common scales and persistent landmarks was preferable. The rule is the shortest transition that preserves object identity, not the most elaborate one that can be built.

Immersion specifically buys nothing on the understanding axis. Kim et al. built four data stories in static, animated and immersive variants — the last adding depth cues, cinematic camera and realism — and ran a within-subjects study on interest, ease of understanding, persuasiveness, trustworthiness and curiosity. Immersive variants were rated more interesting and more persuasive. No condition was judged more understandable or more trustworthy.[5]

The admissibility test

The Codex run states it as a sentence a reviewer has to be able to finish: “This motion lets the reader perceive ___ that would otherwise require a difficult mental comparison.” If the blank is energy, delight, premium quality or immersion, it is decoration and does not draw on the evidence-motion budget.

A transition fails review if it changes unrelated dimensions, loses landmarks, cannot be understood when scrubbed quickly in either direction, creates a long task, or conveys information only while in motion.[6,7,55]

05

Attention

What survives the scroll

Two of the corpus’s most consequential numbers are about behaviour rather than cognition, and they point the same way: readers get less far than the format assumes, and they check sources far less often than the format’s ethics assume.

Chartbeat’s analysis of Slate, drawn from roughly two billion page views, found that of every 161 arrivals about 61 left immediately; of the 100 engaged readers about 5 never scrolled a pixel, around 10% web-wide; median scroll depth was about 50% on Slate and 60% web-wide; and only 25% got past the 1,600th pixel of a 2,000-pixel article. Roughly two-thirds of time on page was spent below the fold, and the relationship between scroll depth and sharing was only very weak — shares are not a proxy for reading.[51]

The verification number is starker. Piccardi et al. instrumented 96 million citation-related events on Wikipedia over two months. An external reference was clicked on 0.29% of page views — 0.56% on desktop, 0.13% on mobile — and 93% of cited URLs received no click at all during the measured month.[37] Clicks were more common on shorter and lower-quality pages, which suggests readers verify when the page has failed them rather than because a marker is visible; that correlation is observational, not causal.

The above-the-fold consequence A median scroll depth near 50% means a structure that withholds its finding until the reader has traversed twelve states is designed for the quarter of readers who reach the end. ProPublica’s house rule points the same way: make the editorial nut of the story the most noticeable thing on the page.[35] The load-bearing conclusion belongs in the first screen or the first two states — which is why this page states its finding before §01.

06

Provenance

Citation is architecture, not decoration

The corpus separates three things that are routinely collapsed into one: whether a source is visible, whether it is credible, and whether it actually supports the exact claim it sits beside. Only the third is what an evidence-dense report is selling, and it is the one no interface can prove.

On visibility and credibility the measured picture is real but modest. In a randomised experiment with 1,183 adults, a bundle of inline footnotes, author information, story type, reporting-method disclosure and organisational standards produced small but statistically significant improvements on four of fifteen organisational evaluations — and the design cannot isolate which indicator did the work.[39] Li et al., N=517, found credibility judgements varied with source attribution and with prior trust in the named institution, while comprehension did not reliably predict perceived credibility.[40] Hyperlinks raise perceived credibility with a small but significant effect, strongest in value-framed conditions.[44] And a single transparency feature had almost no effect where multiple indicators together did; in recall testing only 34% of participants could correctly identify the journalist and only 26% could recall a detail from an editorial explanation they had seen.[42]

Metadata behaves the same way. Readers wanted encoding metadata when trying to understand a chart and source metadata when judging trust; metadata made visualisations appear more thorough without improving extraction accuracy.[41] Qualitative audience work on COVID-19 visualisations found clear source identification and contextual notes supported trust while participants said outright they would not inspect the data — and that likability did not track trustworthiness.[43]

Source presence and source verification are different outcomes, and only the first is under a designer’s control. Design for the reader who checks; do not report the affordance as though it produced checking.

The three-layer architecture

Four runs independently specify the same interface, at different levels of detail. It is worth stating as a spec because it is the part of this corpus that converts most directly into code.

  1. An atomic inline marker, adjacent to the smallest span the source supports. Not attached to a paragraph carrying several propositions. If a claim is quantitative or attributed and has no marker, the build fails.
  2. A preview available by hover, keyboard focus and tap. It carries source title, author or organisation, date, evidence type, the specific table or section, a one-sentence statement of what the source supports, and a direct link. Activating the marker opens the preview rather than navigating away. Keyboard activation, escape to close and focus return to the invoking control are mandatory.[68]
  3. A persistent, de-duplicated registry. Full bibliographic metadata, evidence tier, publication and access dates, limitations, and backlinks to every claim that uses the source. A bibliography without claim mapping is inadequate for this form: it makes the report look sourced while leaving individual claims unverifiable.[37,20]

The rule that constrains all three comes from the NYT graphics desk, and it is old enough to be settled practice: if you make a tooltip or rollover, assume no one will ever see it — if content is important for readers to see, don’t hide it.[34] Any design in which a source exists only inside a hover state has, by that rule, no sources. The preview is a convenience layer over a registry that must work without it. One run nominates FiveThirtyEight’s expandable inline footnote as the reference implementation, though its support for that is a blog post rather than a measurement.[84]

Two Wikipedia numbers, routinely conflated Wikipedia produces the corpus’s two headline citation figures and they measure different features. Piccardi et al.’s 0.29% is reference click-through. The Wikimedia Page Previews A/B tests, which found a 31% increase in overall page interactions, measured article-link hover previews — a different feature with a separate Reference Previews product and no comparable published result. Transferring the 31% to citation hovercards is not warranted, and only one run in the panel says so.[38,37]

One more finding belongs here, because it changes how an automated report should disclose itself. A systematic review of 47 studies on AI provenance and disclosure cues in journalism found effects on perceived credibility to be predominantly null or conditional: there is no uniform AI penalty, and disclosure cues do not act as warning labels that reduce trust.[45] Disclosing that a page was machine-assembled costs nothing measurable. Concealing it costs everything if it is discovered.

07

Performance

The motion stack, and the argument inside it

The budget is externally fixed and not a matter of taste. Largest Contentful Paint at or below 2.5 seconds, Interaction to Next Paint at or below 200 milliseconds, Cumulative Layout Shift below 0.1 — each evaluated at the 75th percentile of Chrome UX Report field data over a rolling 28-day window, measured separately per device class, with all three required to pass.[52] The 200 ms INP threshold was derived from the 100 ms figure supported by quality-of-experience research and adjusted for achievability, with particular attention paid to lower-end mobile hardware.[53] Below the field metrics sit two frame-level numbers: a 16.7 ms budget at 60 fps, of which roughly 10 ms remains after the browser’s own rendering work,[56] and the 50 ms line above which a main-thread task is formally a long task and can block interaction.[55]

Above the floor, the corpus describes a stack rather than a library choice. The mechanism that separates the tiers is primary-sourced: browsers perform scrolling on a separate process and deliver scroll events asynchronously, and from Chrome 115 Scroll and View Timelines integrate with the Web Animations API and CSS Animations and can run off the main thread, with no scroll listener and no IntersectionObserver.[57] GSAP’s ScrollTrigger, by its own documentation, watches scroll position on the main thread — debounced, synchronised with requestAnimationFrame, and with resize recalculation throttled until there is a 200 ms gap, because recalculating is CPU-intensive.[60] The distinction worth holding onto is that a scroll-driven animation ties progress directly to scroll position, pausing and reversing with it, where a scroll-triggered one merely starts on entry.[79]

GSAP’s documented hazards convert straight into lint rules: do not animate the pinned element itself, because it throws off the measurements; never place will-change or a transform on an ancestor of a pinned section, because that breaks position: fixed; under scrub, child tween durations are proportions of scroll distance rather than real time, so slowing an animation means extending the end distance, never the durations; and create triggers top-to-bottom, because pinning distance affects later triggers’ start and end values.[60] Since April 2025 the full plugin set has been free for permitted commercial use, which removes the procurement argument but not the main-thread one.[62]

Where the panel is arguing with itself

Two runs assert that JavaScript scroll libraries introduce severe INP latency on mid-tier mobile and that the correct response is to move to native CSS scroll timelines.[82,80] Both trace to engineering blogs rather than published measurement. A third run flags exactly this: the two practitioner positions directly contradict each other, both come from vendor-adjacent sources, and the mechanism is primary-sourced while the magnitude is not. A fourth adds the precise qualification that dissolves most of the argument — INP does not directly measure scrolling or hovering; main-thread work degrades INP by delaying the next click, tap or keypress.[54]

The defensible position is the mechanism. Use CSS for compositor-friendly reveals, GSAP for scrubbed sequencing CSS cannot express, and measure your own page rather than importing a number from a blog.

The runs also disagree about whether the CSS layer is ready. One reports support around 85%, all major engines except Firefox, with Safari arriving at version 26.[59] Another reports animation-timeline as a limited-availability, non-Baseline feature as of April 2026.[58] Both can be true — “widely supported” and “Baseline” are different bars — and the build consequence is the same either way: the CSS layer is an enhancement behind @supports, never the only mechanism carrying meaning.

08

Three dimensions

The gate a 3D scene has to pass

Nothing in the corpus establishes a quantitative threshold at which 3D repays its cost; three runs say so explicitly. What all five do supply is a conjunctive gate, and the versions are close enough to merge. The framing that makes it decidable comes from Kim et al.: immersion demonstrably raises interest and persuasiveness without raising understanding or trust.[5] A scene that only raises persuasiveness is rhetoric charged to the reader’s battery.

  1. Semantic necessity. A major claim depends on depth, volume, orientation, topology, occlusion, assembly or movement through physical space — something a 2D encoding loses.
  2. Viewpoint necessity. Changing viewpoint reveals evidence rather than showcasing an object. Every camera or object transition maps to a claim; there is no decorative idle orbit.
  3. 2D insufficiency. A map, cutaway, orthographic diagram, annotated image or small multiple cannot communicate the claim at least as clearly. Systematic work finds occlusion, clutter, distortion and scalability are persistent trade-offs for 3D representations of abstract data, and a network study found 2D better for spatial-memory tasks.[67]
  4. Comparative value. A prototype beats the best 2D alternative on comprehension, accuracy, completion time or error — not on preference.
  5. Operational fitness. It meets the same field thresholds and frame budget on the target mobile tier, with a capped device pixel ratio, compressed assets, bounded draw calls and VRAM, on-demand rendering rather than an unconditional loop,[63] explicit disposal of textures, geometries and materials,[64] and context-loss handling.[65] The two production killers named repeatedly are raycasting against every object on every pointer move, and failing to dispose removed objects so GPU memory grows until the tab fails — both survive review because both work fine in a short demo.[83]
  6. Equivalent fallback. A static image, 2D projection, table and narrative description communicate the same conclusion when WebGL, motion or JavaScript is unavailable.

The sixth gate is not optional politeness; it is forced by a measurement problem. 14islands’ production post-mortem reports that some browsers claim WebGL support but are too weak to run it well, and that there is no robust way to feature-detect powerful devices — frame-rate measurement and feature combinations all have flaws — so they infer capability from screen size and layer the canvas over a page that is already complete and crawlable.[66] If capability cannot be detected, the only safe architecture is one where the page is finished before the canvas arrives — the HTML-first rule another run states as “every meaningful page state must exist as crawlable markup before the renderer ever boots”.[81]

Fail any evidence gate and the correct output is an annotated static graphic or a scrubbed 2D transition. Fail an operational gate and ship the fallback until it passes.

09

Accessibility

The floor is a floor

The applicable criteria are asymmetric in legal weight, and the asymmetry matters for a build spec. 2.2.2 Pause, Stop, Hide is Level A — moving, blinking or scrolling content that starts automatically, lasts more than five seconds and runs in parallel with other content must have a pause, stop or hide mechanism unless essential, and movement begun by general interaction such as scrolling may fall under it.[69] 2.3.3 Animation from Interactions is Level AAA and covers scroll parallax explicitly.[70] Relying on that distinction is unsafe: scroll-triggered movement can engage the Level A criterion depending on how it behaves.

The architectural choice inside all of this is reduced-first. Two implementations exist: motion-first, where full animation is the default and is disabled under prefers-reduced-motion: reduce; and reduced-first, where a static baseline is the default and motion is added only under no-preference. Reduced-first fails safely, because a browser without the query simply ignores the no-preference block and leaves the static baseline standing.[73] W3C’s own technique note is the reason this matters beyond compliance: if scrolling causes elements to move other than the essential movement of the content itself, it can trigger vestibular disorders.[71]

A number to stop repeating One run states that roughly 35% of adults over 40 experience a vestibular disorder, and treats it as load-bearing. Another explicitly flags the same figure as circulating through accessibility guides without a traceable epidemiological citation. The design conclusion does not depend on it — W3C’s normative technique is sufficient authority — and quoting an untraceable prevalence figure in a report about evidence discipline is the sort of thing this page exists to catch.[71]

Two further rules survive all the runs that address them. A pause control that appears only on hover or focus fails, because readers who cannot use a mouse precisely, or who navigate by voice, may never trigger it. And screen readers should not receive a live-region announcement for every scroll state: the stable prose carries the narrative, and live regions are reserved for deliberate control actions whose results would otherwise be unavailable. The two-tier text alternative that newsroom practice has settled on is a concise description naming chart type and primary conclusion, plus a structured data table ordered thoughtfully rather than dumped.[74,75]

This has moved from advocacy into process. A Reuters Institute fellowship found blind audiences were missing crucial COVID-19 health information presented visually; the output was new BBC alt-text guidance, published externally and used to train roughly 800 staff journalists, and the same work notes the NYT created an Accessibility Visuals Editor post.[36]

The gap nobody filled No run found a published newsroom standard for how a screen-reader user should experience a sequence of scroll-triggered states — whether steps should be exposed as a live region, as a linearised article, or as a parallel static document. Alt-text standards are public. This one is not.

10

Failure

The failure modes, in order of how well they are documented

Scrolljacking — the best-evidenced failure in the corpus

NN/g’s usability testing across multiple industries found the majority of participants experienced at least mild disorientation, with some reading the effect as a broken page. On a fully scrolljacked page every participant who visited was disoriented: one got lost, could not follow the story, and called backtracking a hassle; readers re-scrolled repeatedly, switched to dragging the scrollbar, refreshed, or abandoned. Short scrolljacks preserved orientation but produced an illusion of completeness — users assumed the page had ended. Mobile amplified every problem.[21]

That testing is qualitative, and one run notes it could not retrieve the quantitative counterpart. Another run retrieved it: a controlled study with 20 participants comparing matched scrolljacked and standard prototypes found no significant speed benefit, and significantly lower accuracy and satisfaction.[22] That single recovery is the clearest demonstration in this corpus of what a panel buys over a single run.

The definitional line matters for a build spec, and it is routinely blurred: scrollytelling monitors scroll and changes content; scrolljacking manipulates the browser’s scroll mechanics. The first is the pattern, the second is the anti-pattern.[25] Bostock reaches the same verdict from the mechanics: snapping requires inferring swipes from wheel events, which yields hypersensitivity, dropped gestures, loss of the scrollbar, loss of keyboard control and loss of rubber-banding.[23]

Mobile collapse

The post-mortems are specific. Newsday used an inner scrolling container to stabilise mobile browser bars and documented clipped text and disabled effects on smaller screens — evidence available only at particular viewport dimensions.[30] The Washington Post’s eclipse scroller faced an image load of 30 MB or more before adopting lazy loading and sub-10 KB thumbnails.[31] The Pudding’s responsive guidance is the most directly convertible: size steps in pixels computed from window.innerHeight and never in vh, because mobile navbars appear and disappear during scroll and change the viewport height; sync JS and CSS breakpoints through matchMedia; separate chart setup from chart draw; no steppers; no hover-only content; and stack instead of scroll whenever the transitions are not carrying meaning.[24] Tse’s estimate of the real cost still stands: a graphic needs redesigning two or three times to work on both desktop and mobile.[34]

Misleading and under-labelled charts

This is the failure with the largest measured effect sizes anywhere in the corpus. Pandey et al. tested truncated axes, area-as-quantity, aspect-ratio distortion and inverted axes across 330 participants: those exposed to deceptive visualisations reported interpretations 58.5% to 129.5% larger than controls, and under an inverted axis 97.5% of the deceptive group answered incorrectly. Chart familiarity, visual ability and education produced no conclusive protective correlation.[46] A five-study programme found 83.5% of participants showed a truncation effect and that instruction did not eliminate it.[47] Readers have near-universal difficulty identifying construction errors such as truncated axes, dual scales and missing legends without assistance.[48]

The consequence for anything automated

Reader sophistication cannot be relied on as a mitigation. Axis integrity, units, denominators, baselines, legends and uncertainty have to be enforced at generation time, by a lint pass, not left to review. Narrative design adds, omits and prioritises information at the data, visual, annotation and interaction layers — all four are places a claim can quietly outrun its source.[17]

Template sameness

The one failure mode with a measurement is homogenisation itself. Goree et al. compared roughly two million pairs of web-page images across 2003–2019: design became less homogeneous from 2003 to 2007, then dramatically more so, in both colour and spatial layout, with layout similarity distance declining 44% between 2010 and 2019. The strongest correlate was shared use of a small number of frameworks and libraries, and their warning is forward-looking — these changes may constrain the perceived repertoire of legitimate designs available to future designers.[49]

No run found a validated metric for whether a specific page reads as templated; three say so explicitly. One run reports an evaluation of an LLM-driven data-journalism agent finding that machines ground evidence well but fail to match the bespoke aesthetic of human teams, producing a recognisable sameness — a finding worth naming precisely because it describes what a generator like this one is at risk of.[78] What the runs offer instead of a metric is a boundary all of them draw in the same place. Standardise the hidden infrastructure; do not standardise the visible rhetoric. The Financial Times built reusable story patterns around specific reader questions rather than generic layouts, introducing each only after it had worked on a prominent story.[33] The Washington Post’s post-mortem warns against copying a successful interactive instead of finding the approach the next story needs.[32] And a caution against over-correcting: cartoon styling and hand-drawn fonts measurably reduced perceived credibility, so distinctiveness is not the same as decoration.[50]

A page fails the authorship review if its section silhouette matches the previous report once colour and copy are removed; changing the subject noun leaves the visual metaphor intact; motion is mostly repeated fade-slide-reveal recipes; typography and illustration are unrelated to the source material; the hero is more specific than the evidence beneath it; the same chart grammar appears regardless of data type; or the page carries no editorial tension, uncertainty or counterargument.

12

Convergence

What all five back

Six of the ten are unanimous, and all six are about how to build the thing. Read down the columns and one run stands apart; read across the rows and the production rules are settled while the claims about effect are not. That is the shape of this corpus: a mature craft with an unsettled warrant.

The build spec

What follows is the subset no run contradicts, stated as things a build can fail on rather than as advice.

  1. Compile a claim graph before designing a page. Every claim carries an identifier, exact text, a confidence qualifier, a direct-or-inference flag, source identifiers, the supporting excerpt or data location, scope and limitations, and the visual states that use it. The build fails if a quantitative or attributed claim has no source, if a cited source supports only a nearby proposition, or if an inference is rendered as a direct finding.[17]
  2. Emit a complete semantic document first. Headings, prose, tables, chart descriptions and the full source registry in meaningful DOM order, pre-rendered, readable without JavaScript.[28] Enhancements may disappear; evidence may not.
  3. Default to the martini glass. Contract, orientation, progressive proof one claim at a time, complication, synthesis, then exploration and provenance.[1] Put the load-bearing conclusion in the first screen.[51]
  4. One claim per scroll state, rendered idempotently from its own identifier. Adjacent states reuse objects, scales and positions unless the change is the evidence.[6,26]
  5. Spend motion only on transitions between related states. Count semantic transformations, not tweens. Animate transform and opacity; keep per-frame layout and paint out of the loop.[7,6]
  6. Never touch scroll mechanics. No altered rate, direction, momentum or history behaviour; no normalizeScroll(); native document scrolling with position: sticky where pinning is needed.[21,22,60]
  7. Reduced-first motion architecture, plus a visible motion control. Static baseline; motion added only under no-preference; the control must be persistently visible, not hover-revealed.[73,69]
  8. Three-layer citation, with the registry as the source of truth. Marker, preview, persistent de-duplicated registry with backlinks. Nothing may exist only inside a hover state.[34,37]
  9. Lint every chart for construction integrity. Axes, units, denominators, baselines, legends, uncertainty. Reader sophistication is not a mitigation.[46,47,48]
  10. Gate 3D on the six tests in §08, and ship the fallback until every operational test passes.
  11. Release against field thresholds, not assumptions. LCP ≤2.5 s, INP ≤200 ms, CLS <0.1 at the 75th percentile; no main-thread task over 50 ms; full content parity under reduced motion and with JavaScript disabled.[52,55]
  12. Standardise the chassis, derive the appearance. Share semantics, citations, accessibility components, performance harness and motion APIs. Derive composition, typography, chart grammar and transition metaphor from the subject.[49,33,32]

13

Limits

What none of the five could answer

The gaps below are the ones every run independently recorded as gaps. They are not areas where the panel was lazy; they are areas where the public record is empty.

  • Step-level completion for a real published piece. No newsroom publishes per-step funnels, so the operational question — how many scroll states a report can carry before the argument stops arriving — has no answer. The 2013 median-scroll-depth figure is a web-wide average standing in for a format-specific number.[19,51]
  • A matched motion benchmark. Nobody has published INP and long-task counts for one representative page implemented three ways — CSS scroll timelines, IntersectionObserver, and GSAP with scrub — on mid-tier mobile under CPU throttling. This is the only decision in the whole build spec where the practitioner literature contradicts itself and no measurement exists.
  • The winning citation affordance. Wikipedia establishes that verification is rare and what correlates with it. No study in the corpus compares inline links, numbered footnotes, hover previews, click popovers and side panels for claim verification in a long-form visual report.[37]
  • Whether good citation UX makes readers verify. Not corroborated in either direction. What is supported is narrower: preview affordances lower exploration cost, and multiple co-present transparency signals raise perceived credibility more than one does.[38,42]
  • A metric for template sameness. Three runs record that none exists. Goree et al.’s method — pairwise similarity over colour and spatial layout — is the closest available, and turning it on a producer’s own output corpus would convert an unfalsifiable design goal into a gate.[49]
  • Any universal budget. No authoritative limit generalises for JavaScript transfer size, simultaneous tweens, active triggers, draw calls, polygons, texture memory or device pixel ratio. Device-tier testing and field telemetry are the only defensible route.
  • Assistive-technology testing of production scrollytelling. WCAG supplies clear requirements; comparative task-based testing with VoiceOver, NVDA, TalkBack, keyboard navigation, zoom and reduced motion on real published pieces is sparse to absent.

Colophon

How this page follows its own rules

Structure

Martini glass: the finding sits above §01, the argument runs one claim per section, and the registry and limits open at the end. It is a document with bounded visual episodes rather than a pinned scroller, which is what the corpus recommends and what survives with JavaScript off.[1,28]

Motion

Two effects, both compositor-only and both behind @supports (animation-timeline: …). A scroll progress rule, which stays on under reduced motion because it is a position indicator driven by the reader’s own scroll. And a chapter entrance — 8 px and opacity, on section headings only — which is additionally gated on prefers-reduced-motion: no-preference. Reduced-first, so a browser without the feature keeps the static baseline. No scroll listeners, no parallax, no scroll-mechanics interference, no library.[73,57]

The effect that fails its own test

The chapter entrance would not survive the admissibility test in §04. It marks a boundary; it does not make anything easier to perceive. That is why it sits behind a visible toggle and is off by default under reduced motion, and why the progress rule — which Segel & Heer name as an under-used narrative tactic — survives the toggle while the entrance does not.[1,69]

The motion control

Persistently visible rather than hover-revealed, keyboard reachable, and it overrides in both directions rather than only disabling. A pause control that appears only on hover fails the criterion it is meant to satisfy.[70]

Citations

Three layers, as specified in §06. Each marker is a real anchor into the registry, so with JavaScript disabled it still resolves; the preview is an enhancement that opens on focus, tap and hover, is itself hoverable, closes on Escape and returns focus. Every registry entry carries backlinks to the claims that use it.[34]

Performance

One file, no network requests of any kind: no web fonts, no CDN, no images. Charts are hand-authored inline SVG with an accessible name, a description and a data table. The type is a system serif and a system monospace, which is a design choice the performance floor happens to reward.[52]

Where the only available support was a promotional or engineering-blog source, the claim says so rather than borrowing the authority of the surrounding citations. Registry entries are tagged by evidence tier.
