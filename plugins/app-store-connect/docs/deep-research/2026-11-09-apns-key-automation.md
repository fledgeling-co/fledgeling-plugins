# Can an APNs authentication key be created programmatically? (as of 2026-11-09)

## Executive Summary

- **High confidence:** Apple's public App Store Connect API has no endpoint that creates an APNs authentication key. Apple's API-key documentation covers App Store Connect API keys only, generated by hand in the web UI, and says they cannot be used for other Apple services (https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api.md). An Apple forum answer states the same for APNs keys directly (https://developer.apple.com/forums/thread/125026); that thread is undated in the registry and is several years old, so its present-tense claim is downgraded and rests on the live checks recorded under Knowledge Gaps.
- **High confidence:** a team-scoped APNs key valid for both environments serves every app on the team. Apple's 17 February 2025 announcement says existing keys keep working for all push topics and environments (https://developer.apple.com/news?id=wy4tb0uo), and Expo's setup guide treats one key as covering every app in the organisation (https://docs.expo.dev/push-notifications/push-notifications-setup).
- **Medium confidence:** topic-specific keys come in pairs, one per environment. This rests on developer write-ups rather than Apple text (https://github.com/pagis-co/pagis/pull/179), and OneSignal refuses single-environment keys outright (https://documentation.onesignal.com/docs/en/ios-p8-token-based-connection-to-apns).
- **Medium confidence:** a private Developer Portal endpoint does create push keys, because Expo's EAS CLI generates one after an Apple ID sign-in (https://docs.expo.dev/push-notifications/push-notifications-setup). It is undocumented and outside the public API.

## Detailed Findings

The App Store Connect API authenticates with a JWT signed by an App Store Connect API key, and those keys are created by hand in App Store Connect and work only against that API (https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api.md). No APNs key resource appears in that documentation, and the forum answer says the portal is the only method Apple provides (https://developer.apple.com/forums/thread/125026).

Since 17 February 2025 the portal offers two restrictions on a new APNs key: team-scoped keys can be limited to the development or production environment, and topic-specific keys bind to one bundle ID. Keys created before that date keep working for every topic and environment (https://developer.apple.com/news?id=wy4tb0uo). Developer projects that adopted topic-specific keys hold one per environment (https://github.com/pagis-co/pagis/pull/179), and at least one push provider accepts only keys valid in both environments (https://documentation.onesignal.com/docs/en/ios-p8-token-based-connection-to-apns).

Role matters for anyone automating this through a session: on an individual account only the Account Holder can generate signing credentials, and on an organisation the Account Holder and Admin can, with App Manager allowed only when given Certificates, Identifiers & Profiles access (https://docs.expo.dev/app-signing/apple-developer-program-roles-and-permissions).

<INFERENCE from="https://developer.apple.com/news?id=wy4tb0uo, https://docs.expo.dev/push-notifications/push-notifications-setup">For a team that ships several apps, creating one team-scoped Sandbox & Production key once and reusing it removes the per-app need for key creation entirely, so the absence of an API costs one manual step per team rather than one per app.</INFERENCE>

## Knowledge Gaps

- No academic literature bears on this; the academic task searched deliberately nothing and is recorded as an established negative.
- The live checks that carry the present-tense claim are local measurements, not registry sources: on 2026-11-09 `asc certificates create --help` (asc 6.2.0) listed 18 certificate types and none for APNs, `asc search "apns key"` returned only alternative-distribution keys, and `asc capabilities` lists Sign in with Apple key creation through private portal endpoints but no APNs key command.
- Whether Apple caps the number of APNs keys per team was not established.

## Recommended Next Steps

- Treat the APNs key as a per-team asset: one team-scoped Sandbox & Production key, created once by the owner in the portal and stored in a secrets broker.
- Re-run the asc checks above when asc ships a new major version, since its private-portal key commands already cover Sign in with Apple keys and could grow an APNs one.
