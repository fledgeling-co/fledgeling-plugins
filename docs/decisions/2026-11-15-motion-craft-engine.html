Which engine should motion-craft render videos with by default?

Decided

The decision

Render through HyperFrames, pinned to 0.9.52, local only, with telemetry switched off and its usage beacon and HeyGen media steering left out; motion-craft is the director layer on top.

4 of 4 models · confidence medium

Why

HyperFrames is Apache-2.0, an existing library as the owner asked, and already does the deterministic frame-by-frame render, the editable Studio preview and the check, snapshot and audio measurement the skill would otherwise build. Every lane made it conditional on two facts, and both checked out on this machine: its docs say you can create and render locally without an account, telemetry turns off with HYPERFRAMES_NO_TELEMETRY=1 or DO_NOT_TRACK=1, and a 10-second 1080p test film rendered locally in 19 seconds. Bundling GSAP failed the licence gate, Remotion charges companies of four or more, and an own runtime would rebuild what design-craft and HyperFrames already ship.

What happens next

  • Write motion-craft's engine reference around pinned npx hyperframes@0.9.52 with HYPERFRAMES_NO_TELEMETRY=1 and DO_NOT_TRACK=1 on every command, no usage beacon, and no HeyGen paid media without the user's approval.
  • Keep the director layer (story, rhythm, craft, sound, review) engine-independent and name design-craft's plain HTML timeline engine as the fallback when the user declines the vendor CLI.

How this was decided

  • Four models from four families answered the same evidence pack independently with the options in swapped order; all four chose C in round one, so no second round ran.
  • The two conditions every lane attached were checked against HyperFrames' own docs and a local render before deciding.
  • Conditions the lanes raised while agreeing: HyperFrames' player depends on GSAP, which installers fetch through npx so the plugin redistributes nothing (Astra); and the skill needs a second capture path if the CLI changes (Grok), answered by the design-craft fallback.
