# Designing an Improved 'ELI5' Skill for Claude Code: Evidence-Based Pedagogical Architectures and Visual Explainer Artifacts

## Executive Summary

*   **(High Confidence)** Direct generation of Scalable Vector Graphics (SVGs) by Large Language Models (LLMs) consistently fails due to "coordinate hallucination." Models process numerical coordinates as discrete linguistic subword tokens rather than continuous spatial points, fundamentally lacking geometric awareness and resulting in severe token redundancy and warped outputs.
*   **(High Confidence)** The implementation of the "Drawing-with-Thought" (DwT) reasoning paradigm dramatically mitigates visual hallucinations. By forcing the LLM through a six-stage scaffolding process—ranging from concept sketching and shape decomposition to coordinate bounding and final assembly—the model grounds its token generation in deduced mathematical logic prior to code emission.
*   **(High Confidence)** The optimal prompt architecture for complex AI explainer artifacts relies on Progressive Disclosure, governed by the `SKILL.md` standard. This technique prevents context window saturation by exposing only lightweight metadata (Layer 1) to the model initially, dynamically loading deep operational instructions (Layer 2) and reference assets (Layer 3) only when triggered by user intent.
*   **(Medium Confidence)** Analogy generation in pedagogical tools must be constrained by Dedre Gentner's Structure-Mapping Theory (SMT). Explanations that prioritize the alignment of deep, causal relational structures over superficial object attributes prevent the formation of persistent instructional misconceptions.
*   **(Medium Confidence)** Multi-agent pipelines, such as the Critic-Visualizer loops observed in the PaperVizAgent framework, outperform zero-shot generation. Separating semantic planning from deterministic spatial layout generation prevents the "open-loop visual blindness" inherent to models that cannot visually verify their own code outputs.
*   **(Medium Confidence)** The current production standard for interactive AI artifacts relies on single-file, sandboxed React Universal Module Definition (UMD) components. However, these are strictly limited by aggressive Content Security Policies (CSPs) that whitelist specific Content Delivery Networks (CDNs), such as `cdnjs.cloudflare.com`, inherently restricting the use of external visualization libraries.

## Detailed Findings: Evidence-Based Pedagogical Architectures and Visual Explanation Techniques

The engineering of highly intuitive, non-jargon visual explanations—commonly referred to as "Explain Like I'm 5" (ELI5) artifacts—requires a rigorous synthesis of cognitive psychology, prompt architecture, and constrained web rendering. The core directive is to generate self-contained HTML/JS/SVG interactive mental models that demystify complex systems without succumbing to cognitive overload, broken visual assumptions, or superficial oversimplifications. <INFERENCE from="[cite: 1, 2, 3, 4]">Achieving this level of pedagogical fidelity demands moving beyond zero-shot text generation into structured, progressively disclosed multi-agent architectures that map explicitly to human cognitive processing limits and relational understanding.</INFERENCE>

### Cognitive Science Frameworks: Managing Load and Relational Alignment

The foundational architecture for any AI explainer artifact must be strictly governed by established pedagogical psychology, specifically Cognitive Load Theory (CLT) and Structure-Mapping Theory (SMT). 

John Sweller's Cognitive Load Theory dictates that human working memory has a strictly finite capacity, processing information through three distinct avenues of load: intrinsic, extraneous, and germane [cite: 3, 5]. Intrinsic load represents the inherent complexity of the subject matter, which cannot be eliminated but must be managed through progressive sequencing [cite: 3]. Extraneous load is the unnecessary mental effort imposed by poor interface design, such as cluttered layouts, ambiguous labels, or disjointed navigation [cite: 3, 5]. Germane load refers to the productive cognitive effort required to build mental schemas and internalize understanding [cite: 3, 5]. In the context of AI-generated web artifacts, extraneous load frequently manifests through the "split-attention effect" and the "redundancy effect" [cite: 6]. When users are forced to divide their focus between a diagram and a separate explanatory text legend, working memory is needlessly consumed by the integration of these disjointed sources [cite: 6]. Furthermore, presenting the exact same information simultaneously in parallel text and audio or redundant text captions competes for the same cognitive resources, causing interference [cite: 6]. Effective AI prompt architectures must explicitly instruct the model to spatially and temporally co-locate related information—placing labels directly adjacent to the elements they describe and utilizing chunking to minimize extraneous load [cite: 6, 7].

When explaining abstract scientific or technical concepts, LLMs frequently rely on analogies. However, poorly constrained LLMs often generate superficial metaphors that map object attributes rather than underlying mechanisms, leading to severe pedagogical misconceptions. Dedre Gentner's Structure-Mapping Theory (SMT) provides the cognitive constraint required to engineer effective analogies [cite: 2, 8]. SMT posits that true analogical reasoning involves aligning the relational structures of a base domain with a target domain, entirely independent of surface-level similarities [cite: 2]. The distinction relies on the arity of predicates; attributes are predicates with one argument (e.g., "x is large"), while relationships involve two or more arguments (e.g., "x revolves around y") [cite: 2, 9]. For instance, when an AI explains the flow of electricity, matching the relational mechanism of a water reservoir (pressure, flow rate) is pedagogically sound, whereas matching the physical shape or color of the reservoir is irrelevant and potentially confusing [cite: 2, 9]. Prompt engineering for ELI5 artifacts must incorporate the "systematicity principle" of SMT, instructing the model to prioritize deeply interconnected systems of higher-order relations over isolated, descriptive similarities [cite: 2, 9, 10]. This structured mapping ensures that the AI functions as a rigorous pedagogical tool rather than merely an anthropomorphic conversationalist prone to generating "dead-level" abstractions [cite: 11, 12].

### Visual Representation Patterns: Traversing the Ladder of Abstraction

The transition from textual explanation to interactive visual simulation requires guiding learners from "intuition to mechanism" [cite: 13, 14]. A highly successful architectural pattern for this is the "Ladder of Abstraction," formalized in user interface design by Bret Victor [cite, 123, 126]. The principle asserts that interactive systems should allow users to seamlessly navigate between high-level macro views (concrete concepts) and low-level mechanistic data (abstract implementations) [cite: 12, 15, 16]. 

In the design of AI explainer artifacts, this is frequently implemented via semantic zooming, interactive coding strips, or progressive disclosure panes that adjust the level of detail based on user interaction [cite: 12, 16]. For example, a generated artifact explaining an algorithm should initially present a high-level visual animation of the sorting process (concrete), while providing slider controls or clickable nodes that reveal the underlying state changes and mathematical logic at each step (abstract) [cite: 12, 15]. The failure to provide this interplay traps the learner in "dead-level abstracting," where they are unable to connect abstract rules to concrete outcomes [cite: 12].

### Prompt-Engineering Architectures: Progressive Disclosure and the Coherence Cascade

The primary bottleneck in generating rich interactive artifacts is context window saturation. In dynamic, multi-turn interactive explainer workflows, as the user queries the AI for deeper layers of an explanation, the context window rapidly fills with task-irrelevant information [cite: 17]. This "Context Saturation" leads to "Attentional Residue," where previous topics interfere with current reasoning, causing severe degradation in logical output—a phenomenon extensively documented in the Interleaved Cognitive Evaluation (ICE) benchmark [cite: 17]. 

To mitigate this, modern agentic prompt architectures rely on Progressive Disclosure, operating primarily through the `SKILL.md` specification standard [cite: 18, 19]. Instead of loading a monolithic system prompt containing all possible pedagogical frameworks and CSS libraries, the architecture separates information into three distinct tiers [cite: 4, 19]. Layer 1 (Discovery) exposes only lightweight YAML frontmatter—comprising a skill name and a brief description—to the agent's initial context window [cite: 4, 18, 19]. If the agent determines the skill is relevant to the user's intent, it triggers Layer 2 (Activation), which loads the specific procedural instructions and constraints [cite: 4]. Finally, Layer 3 (Execution/Reference) pulls in dense reference materials, external APIs, or code templates only when explicitly required during generation [cite: 4, 19]. 

The underlying cognitive grounding for why this mechanism succeeds in AI agents is articulated in the "Coherence Cascade" theory [cite: 20]. The theory posits that providing an agent with Layer 1 awareness of unloaded knowledge creates a functional "page fault" within the LLM's processing [cite: 20]. This awareness induces a coherence-seeking drive, transforming retrieval from a passive, rigid instruction into an active, goal-aligned necessity [cite: 20]. By chaining these incentives, the architecture ensures the model maintains a pristine context window while retaining access to arbitrarily deep pedagogical expertise, preventing the hallucinations associated with cognitive overload [cite: 19, 20].

### Documented Failure Modes and Architectural Mitigations

The attempt to generate self-contained HTML/SVG artifacts via zero-shot prompting exposes several severe, well-documented failure modes. 

The most prominent failure is "Coordinate Hallucination" [cite: 21]. LLMs fundamentally lack a continuous spatial mental model; they process geometry as discrete text tokens. When a model encounters the coordinate "120", it does not interpret it as a spatial location, but rather as a sequence of discrete subword tokens (e.g., `["1", "2", "0"]`) that happen to co-occur in its training data [cite: 21]. Consequently, when an LLM writes raw SVG paths (e.g., `<rect x="50" y="80" width="200" height="120"/>`), it is performing statistical token prediction rather than geometric placement [cite: 21, 22]. Researchers utilizing the HiVG framework documented that this lack of geometric awareness results in "severe token redundancy," where simple shapes balloon into hundreds of tokens, destroying spatial accuracy and resulting in overlapping, warped, or geometrically invalid visuals [cite: 21]. 

A secondary failure mode is "Open-Loop Visual Blindness" [cite: 21, 22]. Unlike diffusion models, which have a built-in feedback loop evaluating visual quality during training, SVG-generating LLMs produce code evaluated strictly against a text target [cite: 21]. The training process never renders the SVG to verify if it actually looks correct. Consequently, an LLM can produce perfectly valid XML syntax that renders as visual garbage—boxes overlapping, labels spilling past borders, and arrows cutting through text—because the model cannot "see" its own output to correct it [cite: 21, 23].

To mitigate these fatal flaws, engineering pipelines utilize the "Drawing-with-Thought" (DwT) reasoning paradigm and multi-agent critique-correction architectures [cite: 1, 24, 25]. The DwT framework forces the LLM to emit explicit design rationales before generating any rendering code, effectively scaffolding the process into six sequential stages [cite: 1, 26]. The model must sequentially execute Concept Sketching (identifying silhouettes), Canvas Planning (establishing `viewBox` and margins), Shape Decomposition (breaking objects into geometric primitives), Coordinate Calculation (creating a "mental bounding box" with numerical grounding), Styling and Coloring, and Final Assembly (managing z-index occlusion) [cite: 1]. By enforcing this intermediate chain-of-thought, the model bypasses raw statistical guessing and anchors its token generation in deduced mathematical and spatial logic [cite: 1, 26].



Beyond DwT, multi-agent frameworks like PaperVizAgent and EduVisAgent introduce necessary deterministic safeguards [cite: 24, 27]. These systems orchestrate distinct agents: a Planner Agent translates the pedagogical concept, a Visualizer Agent generates the code, and a Critic Agent analyzes structural integrity in a Generate-Validate-Reflect loop [cite: 24, 28]. Alternatively, the most robust mitigation involves separating semantic meaning from spatial layout entirely. Rather than asking the LLM to generate raw SVGs, the architecture prompts the model to output structured graph data (arrays of nodes and edges), which is then handed off to a deterministic, rules-based layout engine (such as Dagre or a React Flow component) that automatically handles collision detection, grid snapping, and edge routing [cite: 22, 23].

## Detailed Findings: What is the Current State, and What is the Strongest Supporting Evidence for It?

As of mid-2026, the current state of generating interactive visual explainers relies heavily on frontier LLMs orchestrating component-based rendering within strictly sandboxed iFrames. Anthropic's Claude 3.5 Sonnet and OpenAI's GPT-4o are the primary hosted drivers for these environments, while models like Qwen 2.5-Coder (32B and 72B) dominate the open-weights space for specialized code generation tasks [cite: 29, 30, 31]. 

The most robust architectural pattern currently in production is the "Artifact runtime." Rather than outputting markdown code blocks that require user intervention to compile, the LLM emits a complete, self-contained single-page application (HTML/CSS/JS) or a React Universal Module Definition (UMD) [cite: 32]. The strongest evidence for the success of this state is the widespread enterprise adoption of the Claude Artifacts UI, which compiles these components entirely browser-side using an in-browser Babel transcompiler, eliminating the need for complex CI/CD build pipelines [cite: 32, 33]. 

However, this runtime is highly constrained to enforce security, isolation, and determinism. <INFERENCE from="[cite: 32, 33, 34]">Because these artifacts execute in a client-side sandbox without persistent backend state, they are strictly limited to frontend logic, rendering them incapable of executing server-side code or connecting to external databases natively.</INFERENCE> Furthermore, to prevent Cross-Site Scripting (XSS) and supply chain injection attacks, external dependencies are aggressively whitelisted. For example, Claude Artifacts currently only permit external JavaScript libraries to be loaded via a single approved Content Delivery Network (CDN), specifically `cdnjs.cloudflare.com` [cite: 34, 35]. If an LLM hallucinates a dependency or attempts to pull a visualization library from an unapproved CDN like `unpkg` or `jsdelivr`, the artifact will silently fail to render [cite: 34, 35].

To manage the complex prompt engineering required to consistently generate these compliant artifacts, the industry has standardized around Skill Architectures. The viral success of the internal Anthropic `/eli5` skill demonstrates this paradigm shift [cite: 36, 37]. A skill is no longer a massive system prompt; it is a directory containing a `SKILL.md` file that uses YAML frontmatter to broadcast its capabilities, allowing the LLM to selectively load pedagogical instructions—such as adapting vocabulary, tone, and analogy structure based on audience age or profession—only when invoked by the user context [cite: 18, 37, 38]. This modular approach transforms ELI5 generation from a monolithic, token-heavy process into a portable "Capability Uplift" extension [cite: 39, 40].

## Detailed Findings: What are the Contrasting Viewpoints or Competing Evidence?

The primary point of contention in generating visual explainer artifacts lies in the "Build vs. Compose" debate regarding how models should interact with graphical syntax.

**Viewpoint 1: Direct SVG Generation and Optimization**
Proponents of end-to-end visual models argue that LLMs should directly output raw SVG paths or HTML5 Canvas coordinates. Research into specialized models like LLM4SVG argues that with sufficient fine-tuning on high-quality vector datasets, LLMs can overcome coordinate hallucination and generate intricate, semantically aligned SVGs directly [cite: 41]. Advocates argue that bypassing intermediate abstractions allows for infinite creative flexibility and stylized encoding, pointing to optimization-based methods that achieve high CLIPScore and Aesthetic metrics in SVG generation benchmarks [cite: 41].

**Viewpoint 2: Deterministic Layout Engines (Meaning over Layout)**
Conversely, engineering pragmatists argue that treating an LLM as a graphics rendering engine is a fundamental misallocation of compute. Because LLMs lack a visual cortex and operate probabilistically, they cannot reliably perform collision detection, grid snapping, or algorithmic layout routing [cite: 22, 23]. This camp insists that the LLM should only generate the semantic meaning—outputting structured JSON arrays of nodes, edges, and pedagogical text. The actual rendering must be handed off to deterministic, rules-based layout engines (e.g., Dagre) that mathematically guarantee boxes do not overlap and arrows route correctly without intersections [cite: 22, 23]. 

**Viewpoint 3: The DSL Fragility Counter-Argument**
A third viewpoint critiques the use of intermediate Domain-Specific Languages (DSLs) like Mermaid.js. While emitting a DSL safely delegates layout to an engine, DSLs are syntactically rigid and brittle. A single hallucinated pipe character (`|`), a missing bracket, or a misaligned indentation in an LLM's Mermaid output will cause a hard parse error, crashing the entire visual explainer silently without providing actionable recovery feedback [cite: 23]. Therefore, critics argue that generating standard React components using established libraries (like Recharts or Lucide) is vastly superior to bespoke markdown-based DSLs, as React error boundaries can catch and isolate component failures without crashing the entire artifact workspace [cite: 35, 42].

## Detailed Findings: What Changed Recently, and What is the Trajectory?

The most significant recent shift in the AI artifact ecosystem is the transition from stateless visual outputs to stateful, context-aware micro-applications.

Historically, an ELI5 artifact was a static, "single-shot" response. If a user asked for an explanation of a database index, the LLM generated an isolated SVG or text block; if the user wanted to interact or test their knowledge, a completely new prompt generation cycle was required [cite: 36, 37]. Recently, the integration of Persistent Storage and the Model Context Protocol (MCP) has fundamentally altered this trajectory. 

As of mid-2026, platforms like Claude Artifacts introduced persistent state (up to 20MB per artifact), allowing visual explainers to remember user interactions, preferences, and progress across disconnected sessions [cite: 43]. This means a pedagogical artifact can now function as a complete, closed-loop learning environment. Frameworks like Melo's ELI5 mode demonstrate this trajectory: the output is no longer a static explainer but a pipeline where the system presents a visual analogy, transitions seamlessly into a localized "Quiz Mode," and finally initiates an "Explain Back" module utilizing the Feynman technique—all executing within the same stateful sandboxed component [cite: 36].

Simultaneously, the trajectory points clearly toward Skill Distillation and Ecosystem Portability. The open standardization of the `SKILL.md` format means that sophisticated pedagogical prompt architectures are no longer locked to a specific vendor's proprietary web UI. A well-crafted pedagogical skill that forces the LLM to map structural analogies (Gentner's SMT) and avoid cognitive overload can now be loaded natively into IDEs like Cursor, terminal environments via Gemini CLI, or local agent loops running open-source models [cite: 44, 45, 46]. 

Furthermore, the open-source foundation models powering these local pipelines have reached critical performance parity with proprietary endpoints. In 2026, open-weights models like Qwen 2.5 72B and Llama 3.3 70B can fit on a single 80GB H100 GPU (using int4 quantization) while delivering reasoning capabilities that rival GPT-4o and Claude 3.5 Sonnet [cite: 29, 47]. This democratization allows developers to run token-heavy, multi-agent Critic-Visualizer loops locally, drastically reducing the latency and API costs previously associated with generating highly refined, error-corrected visual explainers.
